# @dingji_cherubino/dsh-full-featured-hub

> DeepSeek Harness (DSH) Web 插件：输入框上方**一张 HUD**，HUD 里是**3 栏网格**，**多张卡片同时显示**。
> 每张卡片自己决定占几栏（1–3），放不下的自动换行；**所有面板在同一时刻都是活的** ——
> 关掉一张卡只是隐藏它，不卸载、不重启轮询、不丢状态。

`dsh-hud` 由两个独立插件合并而来：

| 来源 | 现在是什么 |
|---|---|
| `dsh-quota-hud` 1.3.0 | 卡片 **配额**（`quota`，顺序 10，默认占 **2 栏**） |
| `dsh-github-hud` 1.0.0 | 卡片 **GitHub**（`github`，顺序 20，默认占 **1 栏**） |

合并后又加了四个新面板（不是从旧插件搬来的）：**`weather`**（标题栏天气，顺序 30）、**`parcel`**（快递追踪，顺序 40）、**`market`**（股市，顺序 50）、**`bond`**（债市，顺序 60）。

合并带来的不只是"少装一个包"：两个半区（host / browser）都变成了**注册表**，
新功能 = 一个新面板，而不是又一次复制整个插件再抢一个 `order`。

## 布局：**只有一行**，3 栏

**一行，三栏，就这么多。** 所有显示的卡片栏位之和不能超过 `columns`（默认 3）——
想加第四张卡片？加不进去，而且会**明确告诉你为什么**：

- ⚙ 顶栏常驻一枚预算徽标：`已用 3/3 栏`，满了会变色。
- 点一张放不下的卡片：**拒绝**，下面出现一行红字
  「放不下：一行最多 3 栏，现在要用 4 栏。先关掉或缩小一张卡片……再加新的。」
- 会撑破一行的「栏位」按钮加删除线，会撑破的隐藏卡片在点击**前**就打上虚框 ——
  **拒绝在点之前就看得见**，而不是点了没反应。
- 所有能改布局的入口（⚙ 的开关与栏位、标题栏胶囊、面板内部调 `hud.showPanel()`）**走同一个预算检查**
  （`attemptLayout`），所以一行永远撑不破。

默认布局由面板自己声明、外壳推导（`defaultPrefs()`）：**股市 2 栏 + 债市 1 栏 = 3 栏**；
天气在标题栏（不占栏位）；用量 / GitHub / 快递**默认关闭但仍在后台跑**，点 ⚙ 或标题栏胶囊一键换上来。

> **升级提示**：偏好现在是 v2 结构。旧版可能存着"三行 8 栏"，它在新规则下**天生非法**，
> 所以会被丢弃一次并回到上面的默认布局 —— 与其悄悄替你扔掉几张卡片，不如让你在 ⚙ 里自己看到。

一个面板可以贡献**两种东西**（也可以只贡献其中一种）：

| 贡献 | 出现在哪 | 占栏位吗 |
|---|---|---|
| `Component` | 网格里的一张**卡片** | 占，1–3 栏可设 |
| `head` | **标题栏**里的一段小部件 | **不占**，永远只是标题栏一行里的一段 |

天气面板就是 `head`-only：它不占任何栏位，所以**不会挤动你已经调好的卡片布局**；
但它在 ⚙ 里照样有一行（只有显示开关，没有栏数——它没有栏可以设）。
标题栏部件和卡片共享**同一个开关**：关掉只是 `hidden`，**仍然挂载**、
继续轮询、切回来还在（不会重新拉一次、不会丢读数）。

| 规则 | 说明 |
|---|---|
| **栏位数** | 一行分 N 栏，默认 **3**，可在 ⚙ 里设成 1 / 2 / 3 |
| **每卡占几栏** | 每张卡片可在 ⚙ 里设 1 / 2 / 3 栏（面板自己也有一个默认偏好） |
| **放不下怎么办** | **拒绝**并说明原因（见上）。绝不换行、绝不悄悄丢掉一张卡 |
| **关掉的卡片** | 不占栏位，但**仍然挂载运行**，只在标题栏留一个带角标的**胶囊**，点一下回到网格 |
| **窗口太窄** | 窄于 **560px** 自动塌成单栏（只是防止三栏在小窗口里彻底没法读的安全网；阈值刻意压得很低，因为**栏位数是你的设置**—— 700px 下三栏只是挤，不该替你改掉） |
| **高度** | 只有一行，所以 HUD 的总高度 = 这一行里最高那张卡。图表高度都按"紧凑"给的（股市 K 线 176、债市曲线 118、债市 K 线 176 单位），自选列表只画前 5 行 |
| **左右留白** | 卡片铺满 dock 宽度，但两侧各留 **8px**（`HUD_GUTTER_PX`，一个常量两处生效）。`.hud-root` 是 `box-sizing:border-box`，所以这 8px 是**内缩**而不是在 100% 之外再加 —— 之前是 content-box，根节点实际比容器宽 4px、卡片被顶偏 |

例：`股市` 占 2 栏 + `债市` 占 1 栏 = 一行刚好排满；把 `债市` 关掉就空出 1 栏给 `快递`；
想把 `股市` 和 `债市` 都设成 2 栏？第二下会被拒绝 —— 一行只有 3 栏。

⚙ 菜单就是布局编辑器：**栏位数** + 每张卡的**显示开关 / 栏数**。
这些偏好只存在浏览器本地（`localStorage`），面板自己的设置在它自己的抽屉里、宿主侧持久化。

**宽度是唯一的，没有上限、也没有"位置"选项。** `.hud-root` 铺满 dock，`.hud-card` 铺满它 ——
早先版本提供过 通栏/居中/靠右/靠左 四选一，非通栏模式带 620px 上限；问题出在那个偏好会**活得比模式久**：
一次页签点击就把 `align: 'center'` 写进了 localStorage，于是后来"通栏"成了唯一意图，卡片却依然被
钉在 620px 居中栏里。现在没有可被旧键覆盖的宽度规则了，并且挂载时会把 storage 里不认识的键清掉。

## 为什么是"外壳 + 面板"

原来的两个插件各自注册了 `conversation.input.dock` 里的一个 cell（`order` 90 / 91），
各自拥有一张完整卡片：sticky 定位、居中方式、宽度、边框、圆角、阴影、刷新按钮、轮询、
路由前缀、凭据写入实现……**全是重复的**，而且每加一个功能就要再抢一个 `order`。

现在：

- **一个 cell**（`id: dsh-hud`，`order: 90`）承载全部面板；
- 外壳负责：卡片框架、**3 栏网格**、布局编辑器、**保活**、**故障隔离**、定时器工厂、共享工具；
- 面板负责：自己的同源路由、自己的上游查询、自己的 React 组件、自己的抽屉、**自己偏好的栏数**；
- 面板之间**零耦合**：`hud.setBadge()` 上报角标，`hud.showPanel()` 把别的卡片放回网格。

关键设计取舍：

| 取舍 | 为什么 |
|---|---|
| 面板**常驻挂载**，关掉的只是 `hidden` | "同时激活"的字面实现。关掉再打开不重启轮询、不复位轮播、不关闭已展开的抽屉 |
| 栏位用 `data-cols` / `data-span` **属性**而不是内联样式 | 窄窗口的降级规则能用"同优先级、后声明"直接覆盖；内联样式就得靠 `!important` |
| 每张卡片有**自己的表面**（边框+浅底），外壳只当托盘 | 多张卡并排时必须读成"几张卡"，而不是"一张宽卡里排了几列字" |
| 每个面板包一层 **`PanelBoundary`** | 合并前每个 HUD 独占一个 cell，自己崩只崩自己；合并后必须由外壳保证同样的隔离 |
| 面板**保留自己的卡片 DOM**（`.ocq-card` / `.ghh-card`） | 面板源码可以与被合并的原插件**逐字节保持一致**；外壳用更高优先级（0,2,0）的 CSS 把外层卡片压平成普通块，不修改面板内部一行样式 |
| 栏位与显示偏好存在 **`localStorage`**，且**只读已知键** | 呈现偏好是浏览器本地的事；面板自己的设置在宿主侧持久化，两者职责分明。只读已知键是刻意的：旧版写下的 `align` 就是这么把卡片钉窄的 |
| 面板配置挂在 **`panels.<id>`** 下 | 两个面板都想要 `pollMs` / `timeoutMs`，扁平 schema 必然打架 |

## 加一个面板

**5 步，不动外壳一行代码。**

### 1. `panels/foo/host.js` —— 宿主半区

```js
import { unwrap } from '../../lib/host-kit.js'

export const id = 'foo'
export const order = 30
export const label = { zh: '示例', en: 'Foo' }
// export const storageDomain = 'dsh-foo'      // 可选，默认 dsh-hud/foo
// export function schema(z) { return z.object({ … }) }   // 可选

export function mount(host) {
  const handle = async (req, res) => {
    if (!host.sameOrigin(req)) return host.json(res, 403, { ok: false, error: 'cross-origin-forbidden' })
    const cfg = host.config()                  // 永远读到最新配置
    const token = await host.credential.resolve('FOO_TOKEN')   // 值永不出宿主
    host.json(res, 200, { ok: true, fetchedAt: Date.now(), … })
  }
  host.route('state', handle)                  // → /dsh-hud/foo/state
  return { /* 测试与兄弟面板可用的句柄 */ }
}
```

`host` 提供：`ctx`、`config()`、`route(action, handler)`、`json`、`sameOrigin`、`readBody`、
`credential.{resolve,present,write,remove}`、`storage.{file,read,write}`、`log`、`panel(id)`。
面板**永远不直接碰** `ctx.webServer` / `ctx.credentials` / `$DSH_HOME` —— 这正是它可以被单独测试的原因。

### 2. `panels/foo/client.js` —— 浏览器半区（fragment）

```js
function createFooPanel() {
  function Foo(props) {
    const [data, setData] = React.useState(null)
    React.useEffect(() => {
      let alive = true
      hud.fetchJson('/dsh-hud/foo/state').then((json) => { if (alive) setData(json) })
      // 定时器由外壳注入，别自己读 ctx.timer
      const stop = hud.startTimers(() => { /* poll */ }, 60_000, () => {}, 1_000)
      return () => { alive = false; stop() }
    }, [])
    return jsx('div', { children: data ? 'ready' : 'loading…' })
  }
  // 标题栏部件（可选）。给了它就出现在标题栏，且不占任何栏位。
  function FooHead(props) { return jsx('span', { children: 'Foo 42' }) }

  // span 是"我建议占几栏"（1–3），用户可以在 ⚙ 里改掉。
  // Component / head 至少要有一个：只有 head 就是纯标题栏部件。
  return {
    id: 'foo', order: 30, span: 1, label: { zh: '示例', en: 'Foo' },
    Component: Foo,
    head: FooHead,
  }
}
```

> **fragment 契约**：这个文件会被**原样拼进** `client.js` 的工厂函数体，所以
> **不能有顶层 `import` / `export` / `return`**。所有内部声明都放进 `createFooPanel()`，
> 两个面板的同名辅助函数（`dbg`、`clamp`、`fetchJson`…）才不会打架。
> 构建脚本会强制检查这一点。

### 3. 注册（宿主侧）

```js
// panels/index.js
import * as foo from './foo/host.js'
export const PANELS = [quota, github, foo].sort((a, b) => (a.order ?? 0) - (b.order ?? 0))
```

### 4. 注册（浏览器侧）

```js
// client/register.js
const CLIENT_PANELS = [createQuotaPanel, createGithubPanel, createFooPanel]
```

### 5. 重新生成 bundle

```powershell
node tools/build-client.mjs
```

面板 fragment 是**自动发现**的（`panels/*/client.js`），拼接顺序不影响卡片顺序 ——
卡片顺序由各面板自己的 `order` 在运行时决定。
`span` 只是面板**自己偏好的栏数**：用户在 ⚙ 里的选择优先，且超出当前栏位数时会被夹住。

## 安装

### 方式一：patch 层直接插行（本机采用，**第一次加载不需要重启**）

1. 把插件目录链接进 profile：

   ```powershell
   New-Item -ItemType Junction `
     -Path "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\@dingji_cherubino/dsh-full-featured-hub" `
     -Target "E:\Project\DeepseekPlugin\dsh-hud"
   ```

2. `%USERPROFILE%\.dsh\profiles\desktop\package.json` 的 `dependencies` 加一行
   （让 pnpm 认得这条链接）：

   ```json
   "@dingji_cherubino/dsh-full-featured-hub": "link:E:/Project/DeepseekPlugin/dsh-hud"
   ```

3. 在 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` 末尾追加：

   ```yaml
   - insert:
       - id: hud
         name: @dingji_cherubino/dsh-full-featured-hub
   ```

profile 的 patch 层是**热协调**的：保存后约 1–2 秒插件挂载完成，**不用重启**。
`GET /dsh-hud/quota/usage` 由 404 变 200 就是挂载成功的证据。
浏览器半区需要**刷新一次页面**（boot graph 在插件挂载后重建）。

**同时删掉旧插件的两处声明**，否则同一个卡片会出现两套：

- `cordis.patch.yml` 里的 `- id: github-hud / name: dsh-github-hud` 那一行；
- `package.json` 里的 `"dsh-github-hud": "link:…"`，以及 `dsh.profile.bundles` 里的 `"dsh-quota-hud"`
  （旧 `dsh-quota-hud` 的 link 指向的目录若已不存在，它本来就是空挂的，留着会在下次重启时报
  `Cannot find package`）。

### 方式二：标准 bundle 安装（发布给别人时用）

```powershell
dsh plugin --profile desktop add E:\Project\DeepseekPlugin\dsh-hud
```

即 `dependencies` 加 `link:` + `dsh.profile.bundles` 加 `"@dingji_cherubino/dsh-full-featured-hub"`，由插件自带的
`cordis.patch.yml` 插行。**这条路径新增包必须重启 Harness**（模块解析在启动时建立）。

> ⚠️ 两种方式只能选一种。两边同时声明会让同一个包出现两个 loader entry。

### 改代码之后要不要重启

| 改了什么 | 生效方式 |
|---|---|
| `client.js`（或任何 fragment 重新构建后） | 保存 → **刷新页面**（宿主按 mtime/ctime/size 算 rev 并通过 SSE 推送） |
| `index.js` / `lib/**` / `panels/*/host.js` | **必须重启 Harness**（同一个 URL 已被 Node 模块缓存钉住）。实测：把 `hud` 行 disable→enable 也**不会**重新 import；重启前浏览器半区若已经是新版，天气部件会明确显示「需重启宿主」而不是假装天气坏了 |
| `cordis.patch.yml`（profile） | 即时生效（patch 层热协调） |

## 从两个旧插件迁移

| 项目 | 旧 | 新 |
|---|---|---|
| 包名 / loader id | `dsh-quota-hud` + `dsh-github-hud` | `@dingji_cherubino/dsh-full-featured-hub` |
| dock cell | 两个（`order` 90 / 91） | **一个**（`order` 90），内部 3 栏网格多卡同显 |
| 路由前缀 | `/opencode-quota/*`、`/github-hud/*` | `/dsh-hud/quota/*`、`/dsh-hud/github/*` |
| 配置位置 | 顶层字段 | **`panels.quota.*`、`panels.github.*`（整体下移一层）** |
| GitHub 状态文件 | `~/.dsh/storages/dsh-github-hud/state.json` | **原样继续用**（面板显式声明 `storageDomain = 'dsh-github-hud'`，关注列表、已读水位线、设置全部保留） |
| GitHub 卡片位置 | 面板抽屉里的「位置」 | 已取消：HUD 固定铺满 dock 宽度（原先的面板内「位置」字段也已从抽屉移除） |

```yaml

  config:
    panels:
      quota:
        subscriptions: [ … ]     # 原来在 dsh-quota-hud 顶层的字段整块搬进来
```

## 不做什么（以及为什么）

想清楚"哪些做不到"和实现"哪些做得到"一样重要 —— 尤其当"做不到"的原因是数据里根本没有那个字段时。
每一条下面都写了**验证方式**，不是拍脑袋。

| 需求 | 结论 | 依据 |
|---|---|---|
| 快递**实时刷新** | ✅ 做了 | `www.kuaidi100.com/query` 无 key 可用，实测 144 ms 返回 |
| 快递**服务端推送** | ❌ 做不到 | 订阅推送要企业 `customer`+`key` **加一个公网可回调地址**；桌面插件没有公网入口。已用"轮询 + 变更检测 + 未读徽标"做成行为等价物 |
| 快递公司**自动识别** | ⚠️ 接口版不行，改用本地版 | `autonumber` 现在回 `701 key缺失`；`resultv2=1/4` 对任何单号都回"不是有效的快递单号"。改成**本地正则表**（离线、免费、确定），纯数字给多候选让用户确认 |
| 快递**当前位置地图** | ❌ 做不到 | 把真实响应里所有轨迹节点的键取并集：**只有 `time`/`context`/`ftime`**。没有经纬度、没有 `areaCode` —— 没有坐标就没有图钉可画。卡片改为显示扫描文案里的**地名文本**并注明来源 |
| **外卖实时查看**（美团 / 饿了么） | ❌ 做不到 | 两家**都没有任何公开接口**：订单与骑手位置只存在于各自 App 内，需要用户账号登录态 + 请求签名 + 风控（美团 `mtgsig` 一类）。逆向私有签名接口意味着：必然频繁失效、违反服务条款、而且**我无法测试**（要拿你的账号去跑）。所以不做，也不做一个假装能用的空壳 |
| 外卖**骑手地图** | ❌ 做不到 | 骑手 GPS 只在那两个 App 里；快递接口连坐标都没有，更没有骑手坐标 |

**如果你想要外卖那一栏**，唯一诚实的形式是「一键打开平台订单页」的入口 —— 它没有"实时"价值，
所以我没擅自做。要的话说一声，五分钟就能加。

## 六个面板各自做什么

### `weather` —— 标题栏天气（`head`-only，不占栏位）

标题栏一行显示：**天气现象 + 温度 + 湿度 + 风**，以及**极端天气预警**。点一下展开详情面板
（体感、阵风、降水、风力等级、观测时间、预警列表与原文链接、手动刷新），点外面收起。

| | |
|---|---|
| **刷新** | 每 **10 分钟**（`refreshMs`，下限 60 s），宿主与浏览器用**同一个数字**，不会各说各话 |
| **当前天气** | Open-Meteo `api.open-meteo.com/v1/forecast`（WMO 天气码 → 中文/英文 + 符号；风向取 8 方位，风速换算蒲福风级）|
| **定位** | ① 配置的经纬度 → ② 配置的城市名（Open-Meteo 地理编码）→ ③ **IP 定位**（ip-api，中文名；ipwho.is 兜底），结果缓存 24 小时 |
| **预警** | 中央气象台 `www.nmc.cn/rest/findAlarm`，**一次请求取全量**（`pageSize=1000`，当天 891 条），零分页盲区 |
| **零配置** | 上面四个接口**都不需要 API key**，装完直接有；定位失败会给可执行的提示面板而不是空白 |

**预警是按行政区划代码匹配的，不是猜的。** NMC 的每条预警只有 `alertid / issuetime / title / url / pic`
五个字段，看起来无从下手——但 `alertid` 的**前两位就是省级行政区划代码**（52 贵州、32 江苏、11 北京…，
已对着真实响应逐条验证）。所以：先按**城市名出现在标题里**匹配（`scope: 'city'`，这条预警是针对你的），
没有才退到**同省**（`scope: 'province'`），并且 UI 会**明确标出是"本地"还是"本省"**——
不会把邻市的预警说成是头顶上的。

**实测**（本机真实网络，走插件自己的代码路径）：

```
location   无锡市 / 江苏 / 中国  (source=ip, 31.5618,120.2864)
current    ☂ 毛毛雨 (light drizzle)  23.5°C  feels 24.5°C  humidity 77%
wind       东北 18.3 km/h  级 3  gusts 43.9 km/h
alerts     0  source=nmc  scanned=891        ← 全量扫描，江苏当前确实无生效预警
```

配置（`panels.weather.*`，**全部可选**）：`city`、`latitude`、`longitude`、`refreshMs`、
`alerts`（`auto`/`off`）、`timeoutMs`，以及 5 个端点覆盖字段（测试用，也可指向自建代理）。

### `parcel` —— 快递追踪（卡片「快递」，默认占 1 栏）

粘贴单号就能盯住一个包裹：**多包裹列表 + 完整物流时间线**，有新扫描就标出来。
数据来自 `www.kuaidi100.com/query`（**公开查询接口，无需 key**）。

| | |
|---|---|
| **刷新** | 客户端每 **5 分钟**看一次（`pollMs`），宿主对上游的查询间隔不低于 **15 分钟**（`refreshMs`）——免费接口有限流，而包裹一天也就动几次 |
| **快递公司** | 必选。**19 个代码逐个对着接口验证过**：拿一个假单号去问，回 `ok` 才算数；`tiantian`/`xiyoute`/`feikang`/`pingandad`/`gdkj`/`gtongsudi`/`nantian`/`meiguo`/`sto` 这些到处流传的代码**全部被接口拒绝**（`参数错误`），已剔除 |
| **单号识别** | 本地正则表，**不联网**。`SF…`/`JT…`/`JD…`/`YT…` 这类前缀是明确命中；纯数字只能给**多个候选**（中国单号格式重叠严重），UI 会请你确认 |
| **隐私面单** | 顺丰等需要**手机后四位**，添加时可选填 |
| **时间线** | 接口给的是**最新在前**，宿主统一翻成**时间正序**存储，UI 按快递 App 的习惯**最新在前**展示，并高亮"新"的那几条 |
| **未读** | 不是"新包裹"，而是**时间线动了**：变更键 = 最新节点时间 + 节点数 + 签收标志。动了就标未读、计数上徽标、整行加边框 |
| **状态** | 用接口返回的 `state` 码（kuaidi100 公开语义）：在途/已揽收/疑难/已签收/退签/派送中/退回/转投/清关…，**未知码原样报出来**，不猜 |
| **失败** | 参数被拒时把**接口自己的话**转成可执行的提示（"快递公司代码无效…换一家试试"），而不是糊一个"网络失败" |
| **持久化** | `~/.dsh/storages/dsh-hud/parcel/state.json`（关注列表 + 未读水位 + 快照），重启后还在，且**先渲染缓存再刷新** |

**关于"推送"**：真正的服务端推送（快递100 的订阅接口）需要**企业 customer + key + 一个公网可回调的地址** ——
桌面插件没有公网入口，所以**这条做不到**。这里做的是行为上的等价物：轮询 + 变更检测 + 未读徽标 + 新节点高亮，
有新动态时它自己会亮。

**关于"当前位置的地图"**：**做不到，因为数据里没有坐标。** 把一次真实响应里所有轨迹节点的键取并集，
结果**只有 `time`、`context`、`ftime`** —— 没有经纬度、没有 `areaCode`。所以卡片显示的是**扫描文案里的地名文本**
（`【无锡市】…` → 无锡市），并明确标注"取自扫描文案，接口不提供经纬度"，而不是画一个放不准的图钉。

配置（`panels.parcel.*`）：`pollMs`、`refreshMs`、`timeoutMs`、`queryUrl`（可指向代理/镜像/将来的付费接口）、
`extraCarriers`（`code:名称,code2:名称2`，补自己的快递公司代码）。

### `markets` —— 股市债市（一张卡，切换显示）

**两张卡并成了一一张。** 股市和债市回答的是同一个问题（我的标的怎么样），而在 3 栏网格里各占一张卡，
就是三分之二行花在同一种表格数据上。现在是一张卡 + 一个切换：

```
[ 股市 ][ 债市 ]      ← 卡片顶部的小切换
```

**两个子卡都保持挂载**，不显示的那个只是 `hidden` —— 和外壳对卡片的 keep-alive 是同一条规则：
切换视图不该重启一次轮询、不该清空你正在看的图，切回来必须是瞬间的。代价是两个都在轮询，
而这正是它们作为两张卡时本来就发生的事。

**宿主半区完全没动**：`market` 和 `bond` 仍然是各自独立的面板，有自己的路由、状态文件和设置。
这张卡只是它们的**客户端组合**，所以拿数据的部分一行都没改。

**测试里的选择器要按视图限定**：两张子卡故意共用类名（债市卡画的是同一个图表组件），
所以 `.mk-*` 或 `.hud-k-*` 不限定作用域就会数到两份 —— 每个视图都带 `data-view`，
测试用 `.mks-view[data-view="market"]` 这样的选择器定位。
### `quota` —— 订阅用量（卡片「用量」，默认占 2 栏）

一张克制的原生风格用量卡片，按**实际上报的窗口形状**渲染：

- 有的给 **5 小时 + 周 + 月**（OpenCode GO、智谱 Coding Plan、Command Code）
- 有的只给 **月限额**（Grok、MiMo、千问 Token Plan）
- 有的**不给窗口、只给余额**（DeepSeek、Kimi 预付费）→ 自动切到「账户余额」版式
- **余额 + 近 30 天用量曲线并存时左右分栏**（DeepSeek），整卡更矮

支持的采集源（接口均已对照官方/实践文档核实）：`opencode-go`、`zai`(GLM/智谱)、
`deepseek`（余额 + 私有导出接口的近 30 天 ZIP→CSV 曲线）、`moonshot`(Kimi)、`grok`、
`mimo`(小米)、`openrouter`、`siliconflow`、`qwen`（控制台网关 + 官方 CLI 双路兜底）、
`commandcode`、`custom`（任意 JSON 接口，字段名自动识别）、`custom2`（用户自定义端点 + 字段映射）。

其它：

- **跟随会话 provider**：切到哪家的模型就只显示哪家的计费屏，**绝不拿别家额度顶替**；
  官方 DeepSeek（`deepseek-official`）单独发现。
- **卡片内凭据抽屉**：粘贴 Cookie / token / key / 整条 `Copy as cURL`（自动识别形态），
  保存走 `POST /dsh-hud/quota/credential`（同源校验 + 引用名校验 + 上限），
  宿主优先 `credentials.write()`，兜底原子改写 `.credentials.yaml`；**只回"写到哪了"，绝不回显密钥**。
- **零手动凭据**：Grok（`~/.grok/auth.json`）、Command Code（`~/.commandcode/auth.json`）、
  千问（官方 CLI 设备流）、OpenCode（`~/.opencode/auth.json`）。
- **可执行的提示面板**：需要装 CLI / 配凭据时，卡片里给「请安装 XXX」+ 逐步操作，
  命令一行一个复制按钮、URL 直接可点，而不是甩一句裸错误。
- 用量条是**锚定在整条轨道上的分段渐变**（60% 落位告警琥珀、80% 落位危险橙红），
  外加一条随窗口消耗缩短的**反向时间条**；动画只在**绘制**与**切换**两个时刻发生。

### `github` —— 仓库动态（卡片「GitHub」，默认占 1 栏）

只监控**你自己拥有的**仓库（`GET /user/repos?affiliation=owner`），每个关注仓库一页：

| 消息 | 来源 | 卡片上的样子 |
|---|---|---|
| release / 新发布 | `ReleaseEvent` + `/releases` | `[发布] v2.0.0 · release v2.0.0` |
| push | `PushEvent`（非默认分支） | `[推送] 提交标题 · 3 commits · feature/x` |
| 内容更新 | `PushEvent`（默认分支） | `[更新] bump deps · 2 commits · main` |
| 合并分支 | `PullRequestEvent(closed, merged)` 或含 `Merge pull request` 的 push | `[合并] Fix it · topic → main` |
| 新建分支 / 标签 | `CreateEvent` | `[分支] release/2.0 · new branch from main` |
| issue | `IssuesEvent` | `[Issue] Crash · issue #7 opened` |

- **登录两条路**：设备码流程（默认用 GitHub CLI 的公开 OAuth client id，卡片自己按
  GitHub 给的 interval 轮询授权结果）或粘贴细粒度 token（**先验证再保存**）。
  token 存在 credential `GITHUB_TOKEN`，**只存在宿主侧，浏览器永远拿不到**；未读数上报给外壳，
  显示在标题栏的胶囊上（卡片被关掉时也照样看得见）。
- **自带传输层**（这张网络里很关键）：`api.github.com` 与 `github.com` 可达性经常不一致，
  而 DSH 的进程级代理策略只能启动前设定。`proxy: auto` 会按顺序探测
  环境变量 → 直连 → 本地代理端口（7890/7897/10809/1080/8889），
  取第一个真能连通 `github.com` 的通道并缓存 10 分钟；网络级失败会重新探测并重试。
  只用 `node:net`/`node:tls`/`node:http`，**零依赖**。
- **省配额**：每个仓库每次轮询 3 个请求，全部带 `ETag` 条件请求，`304` 复用缓存且**不计入配额**；
  卡片右下角显示剩余配额。
- **宿主不设定时器**：浏览器按 `pollMs` 拉 `/dsh-hud/github/state`，宿主按需取数并合并并发请求 ——
  关掉所有页面就自动停止轮询。

### 在线数据自检（确认"真的查得到数据"）

单元测试是**离线的**（stub 上游，必须快且确定）。要确认**真能查到数据**，用这个 —— 它挂载真实的
`index.js` → `apply()`，用**真实 schemastery 物化出来的默认配置**，打真实路由，检查**浏览器半区真正读取的那些字段**：

```bash
node tools/live-check.mjs                                        # 就地挂载（重启前也能跑）
node tools/live-check.mjs --url http://127.0.0.1:19387           # 检查正在运行的服务（端到端）
node tools/live-check.mjs --url http://127.0.0.1:19387 --write   # 额外允许写操作（会加一个测试包裹）
DSH_HUD_LIVE_HOME=<你的 .dsh 目录> node tools/live-check.mjs      # 用真实 profile 的凭据/存储（只读）
```

三种结果分开报，因为**处理方式完全不同**：`ok` = 拿到了**有内容**的数据（200 加空数组算 **FAIL**）；
`slow` = 上游限流/超时（面板本来就是降级的，不算崩）；`FAIL` = 插件的问题。

它检查的是**契约**，不是"请求成功"：行情必须有价格（`3842.19` 而不是 `384219`）、K 线必须有
`high ≥ low` 的开高低收、中债曲线至少 6 个期限且收益率 > 0、美债必须有数值、ETF 价格必须 > 1
（防的正是 `fltt=2` 那类把 141.7 算成 0.1417 的错）、自选列表**不能为空**、没有凭据时必须
**给出解释**而不是只回一个空数组。

### 布局：在设置里排列，大/中/小 三档尺寸

**默认布局是这样一张 3×10 的图，三列齐平：**

```
  第 1 列        第 2 列        第 3 列
  股市债市       用量限额       数据库        ← 10 行高
  股市债市       用量限额       数据库
  股市债市       用量限额       数据库
  股市债市       用量限额       数据库        ← 用量 4 行
  股市债市       快递           数据库        ← 快递 3 行
  股市债市       快递           数据库
  股市债市       快递           数据库        4 + 3 + 3 = 10
  股市债市       GitHub         数据库        ← GitHub 3 行
  股市债市       GitHub         数据库
  股市债市       GitHub         数据库
```

**三列都停在第十行。** 中间那列由三张卡组成（用量 4 + 快递 3 + GitHub 3），所以股市债市和数据库
各自也是 10 行。**这个数字是为了齐平而定的，不是量出来的** —— `defaultRows` 正是放这类决定的
地方，而这三张中间卡的高度加在一起**必须**等于两侧的高度，否则最后一列会短一截。

**机器卡已经删除**（不是隐藏）：`panels/machine/` 整个目录、它的两条路由、它的配置命名空间，
以及每个存储里的布局条目。`migrateV10` 会 `delete layout.machine` —— **一个已删除面板的布局条目
不是无害的残留**，它是没有任何东西能显示、也没有任何东西能清理的条目；⚙ 里不会为它提供一行。

**布局的先后顺序就是几何。** 打包算法按 `order` 从上到下做 first-fit，所以 GitHub 的 `order` 必须排在
数据库卡（30）**之后**（40）—— 否则它会挤进第一行的第三格，把数据库挤到别处去。（第一次改就是这样，
测试直接报出 `["markets","quota","github"]`。）

### 为什么"改默认值"到不了已经用过的浏览器

**这一节踩了两次，第二次才是真正的教训。**

**第一次（v8）**：客户端的 `defaultOn` 只影响**全新安装** —— v7 迁移会**保留**每张卡的开关状态
（那是对的：开关是用户的决定）。所以对一个用过的浏览器来说，**`defaultOn` 改了等于没改**。

v8 把"换过格子的那两张卡"的 `hidden` 重新按发布布局应用一次。**结果还是不对** —— 截图显示：
用量和数据库在左列、股市债市在中间、GitHub 在右列。

**第二次（v9）**：因为 v8 **刻意没有动 `order`** —— 而 **`order` 就是几何**。
打包算法按 `order` 做 first-fit，一份 `quota < markets < github < sql` 的旧顺序
排出来就是"左列用量+数据库、中间股市债市、右列 GitHub"：**完全合法，只是没人要**。
再改多少次 `defaultOn` 都动不了一张**位置来自旧版本写下的偏好**的卡片。

**v9 把构成发布布局的那四张卡的几何整个重新应用一次** —— `order`、`span`、`rows`、`hidden`。
别的一张不动：第五张卡的尺寸、任何卡片的折叠状态、其他每一张卡的开关，全部原样。

这四张卡的名字写在 `SHIPPED_ARRANGEMENT` 里，因为**那份名单就是布局本身** ——
一个要重新应用布局的迁移，必须知道布局是由哪几张卡构成的。

**打包顺序是 股市债市 → 用量 → 数据库 → GitHub。** GitHub 排在**最后**，这样 first-fit
会把它放进第一个还空着的位置 —— 也就是用量下面那一格。把它排在第三位，它会占掉第一行的第三格，
把数据库挤走。（测试第一次就是这么写的，断言直接报出 `[0,1,3,2]`。）



**这是这一轮真正的坑。** 客户端的 `defaultOn` 只影响**全新安装** —— v7 迁移会**保留**每张卡的开关状态
（那是对的：开关是用户的决定）。所以对一个用过的浏览器来说，**,`defaultOn` 改了等于没改**：
存储里仍然写着 machine=显示、github=隐藏。

**v8 把"换过格子的那两张卡"的 `hidden` 重新按发布布局应用一次，别的什么都不动。**
尺寸、顺序、折叠状态、以及**其他每一张卡**的开关都原样保留。

为什么不像 v6 那样整盘重排？因为 v6 **必须**：那次面板集合本身变了（股市和债市合成一张卡），
旧排列描述的是已经不存在的卡片。这次集合没变，只是**一个格子换了主人** —— 整盘重置等于为了修一行
而扔掉真实的决定。四大类里被保留的东西，测试逐条钉住：`github.rows = 5` 还在、`order`/`span` 没动、
折叠的卡还折叠着、`markets` 和 `quota` 连看都不看一眼。

**三张卡的尺寸各自独立。** 中间那一列比左右两列多一行，打包算法**留一个空档**而不是把某张卡
压小去凑齐 —— 早先"三列等高"的做法正是机器卡底部那片空地的来源，而空档在网格里是诚实的，
空白在卡片里是骗人的。

**三列高度完全相等，所以网格是一块实心矩形，中间没有洞。** 这是「布局要美观」最实在的一条：
3 栏网格里只要有一列比邻居短，那里就永远是一块空地。股市债市和数据库各占 5 行
（这两张卡内容多 —— 一个要看行情列表 + 费率 + K 线 + 周期切换，一个要放连接表单 + schema 树 + 结果表格），
中间那一列用 2 + 3 补齐（机器有 CPU/内存/磁盘/GPU 四个读数，比用量更吃高度）。

它是打包算法**从一个输入算出来的** —— 顺序，没有坐标、没有特例：股市债市 1 栏宽 5 行高，
于是占掉第一列；用量限额占下两格；数据库需要五行，于是占掉第三列；机器最后只剩三个格子，
正好在用量下面。

**v5 → v6 是一次真正的重排，这是必要的一次。** 上一版把尺寸写成了「面板声明的默认值」，
而那个值只在**全新安装**时生效 —— 于是任何已经有偏好的安装（也就是用户自己的）永远看不到这套布局：
新出现的 `markets` 卡没有存储条目，就退回通用的 3 行，右侧的数据库也是 1～2 行，中间那一列因此散开了。
修法有两处：**声明的尺寸变成了真正的兜底**（`stored → measured → 声明 → 通用默认`），
并且 **v5 → v6 把发布布局重新应用一次** —— 因为**面板集合本身变了**（股市和债市合成一张卡），
从旧排列里反推「用户想要什么」只是把猜测打扮成迁移。保留下来的是每张卡的**开关与折叠状态**：
那些是用户的决定，含义没有变。
### 不滚动，是这一轮真正在做的事

**没有哪张卡应该有自己的滚动条。** 这一轮之前，K 线图和用量卡都在滚动，而卡片下方还空着 ——
原因不是高度不够，是**测量被自己关掉了**：

- 测量循环会**跳过任何有存储高度的卡片**（这是对的：用户手动设的高度不该被测量覆盖）；
- 但 v6 迁移把**四张发布卡片声明的行数写进了存储**；
- 于是最需要测量的四张卡，恰好是**无法被测量**的四张，`max(测量, 声明)` 从来没在它们身上跑过。

**v6 → v7 把这个高度删掉** —— 规则是：存储高度**等于声明值**时删除（那不可能是用户设的，
那是 v6 写的），删掉后得到 `max(测量, 声明)`，即**不低于声明值，只会更高**；
**不等于声明值的高度是用户自己的，原样保留**。这条规则不可能让任何卡片变矮。

（写这个迁移时我自己又踩了一次：`migrateV6` 一开始只是"不覆盖"那个值，而 `defaultPrefs()`
本来就会从 `defaultRows` 播种 `rows`，于是展开后值还在，卡片照样测不了。必须 `delete`，不是"不写"。
测试直接钉住了这一点：迁移后的四张卡 `rows === undefined`。）

### 测量读的是内容，不是布局已经给它的那个框

**卡片高度不对的真正原因在这里。** 测量的代码读的是 `panel.scrollHeight` —— 而那只有在
**面板自己滚动**时才成立。实际上滚动的不是面板，是 `.hud-panel-body{overflow-y:auto}`，
面板只是把它裁掉。于是一张内容溢出的卡片，报出来的是**它已经被分配的高度**：
测量结果和它本该纠正的布局**意见一致**，那张卡片就永远差一行。

这就是用量卡被切掉的「已用 (CNY)」那一行，也是股市债市卡永远长不到能放下 K 线图的原因 ——
而当时我给机器卡"太高了"的判断，同样来自这个数字。

现在量的是 content：**header + gap + body 的 scrollHeight + 面板内边距**。
body 才是知道内容真实高度的那一层；面板只知道它被给了多少。

测试把面板手工搭出来（jsdom 里所有高度都是 0），给它一个 `scrollHeight = 180` 的面板
和 `scrollHeight = 300` 的 body，断言结果 **不是 180** —— 这一条就是那个 bug 本身。

机器卡的高度问题，最后查出来是**行的量化**：

**行高是固定的 78px + 10px 间隙**，所以一张卡的像素高度会向上取整到 88 的倍数。
机器卡的内容约 280px → 向上取整成 **4 行 = 352px** —— 多出来的约 70px 就是卡片底部那片空地。
**它不是留白，是取整。**

三件事一起做的：

1. **磁盘行搬进了 CPU / 内存的仪表盘网格。** 磁盘行本来就是同一个形状（名字、数值、进度条），
   而它外面那层分区多花了一个标题加一个间隙 —— 正是它把内容顶过了一道行边界。
2. **卡片可以声明"上限"（`maxRows`）。** 有了上限，无论取整怎么想都不可能再涨回去 ——
   它只压测量值，**不动你手动设的高度**（那是决定，不是测量）。机器的下限是 2、上限是 3。
3. **"Windows 不提供 load average"那句话删掉了。** 它是卡片的最后一行，等于花一行高度
   去解释一个"读数不存在"已经说明了的事 —— **卡片不是解释自己缺什么的地方**。
   宿主侧干脆不再发这个字段。

写上限的时候，`registerPanel` 的白名单**又咬了我一次** —— 和当初 `defaultRows` 一模一样：
字段没列进那个对象就被静默丢掉，声明变成一句写给自己看的注释。两处都补上了，注释里也写明了这个陷阱。
（另外 `defaultPrefs` 里第一版写成 `Math.min(下限, 上限)`，那会把它钉在**下限**上 ——
上限的含义是"这张卡最多需要多高"，所以默认值应该就是上限。）

- **留白**：四个读数加一行说明散布在五行高的留白里 —— 行距 8→5px、分区上边距 7→5px、表盘行距 4→3px。
- **声明的下限**：`max(测量, 声明)` 让一张卡至少和它的声明一样高，于是**声明高于内容就是空白** ——
  机器卡的 3 行下限正是底部那片空地的来源，现在是 2 行，只用来防止卡片塌掉。
- **那句话本身**："Windows 不提供 load average" 是卡片的**最后一行**，等于花一行高度去解释
  一个"读数不存在"已经说明了的事。**卡片不是解释自己缺什么的地方**，现在 Windows 上
  payload 里干脆没有 loadavg，界面里也不提它。

于是三列不再强行等高：左右两列（内容重的两张卡）仍然在同一行结束，中间一列**比它们早一行** ——
因为它的两张卡各少需要一行。想摆成实心矩形，就得往卡片里塞空白，而空白正是用户刚刚指出的问题。

### 横向滚动条：一个 padding

`.mk-wrow` 同时写了 `width:100%` 和 `padding:4px 7px`，而 `box-sizing` 默认是 `content-box` ——
于是每一行都比卡片宽 14px，**两个像素的留白换来一条满宽的横向滚动条**。
同一个文件里其他规则都手写了 `box-sizing:border-box`，唯独这一条忘了。

这次没有去补那一条规则，而是**在整个 HUD 里设置一次**：`.hud-root *{box-sizing:border-box}`。
这是一整类 bug —— 每个写了 `width:100%` 的面板都得记得这件事，忘了的那个就会在某个截图里
被找出来。设一次，面板就没法忘。

**K 线图的高度也固定了。** `preserveAspectRatio="none"` 配 `height:auto` 会让 SVG 的**高度跟着卡片宽度走**：
一张 1200px 宽的卡片把本该 200px 的图画成 330px，于是**卡片高度取决于窗口多宽**。
现在高度用设计值，SVG 只做横向拉伸（这正是 `preserveAspectRatio="none"` 的用途），
卡片高度不再随窗口变化。

**上限和余量也跟着放开**：`MAX_ROWS` / `AUTO_MAX_ROWS` 8 → 12（一张需要 10 行的卡片，
手动也设不到 10 行 —— 上限本身也是图被截断的原因），留给输入框的保留高度 88px → **72px**，
整体 HUD 因此比原来多出 32px。72 仍高于输入框本身的高度：那是余量，不是输入框的框。
### 折叠：更多卡片共存的前提

高度是 HUD 最稀缺的资源，而且是被**量出来**的（见上文 `--hud-max`）—— 输入框的生存空间不能被挤。
所以再加卡片之前，先给卡片一个折叠态：

- **折叠 = 一行**。面板外面包一层 `.hud-panel-body`，折叠时 `max-height:22px; overflow:hidden`，
  裁到的正好是每个面板自己那行标题。面板内部**一行都不用改**，而且对"根节点 + 卡片"两层结构的旧面板同样成立。
  （写成"隐藏除第一个子元素之外的所有子元素"会在嵌套深度不同的面板上失效。）
- **折叠的卡片只占 1 栏**，不是它自己的 span。这才是折叠的意义：`attemptLayout` 与 `fitsColumns`
  都按折叠后的宽度算，于是原来被一张 2 栏卡占满的行，能同时放下 3 张折叠卡。
- **两个手势**：⚙ 里每张卡一个折叠按钮（可发现、可访问、带 `aria-pressed`），以及**双击卡片**（快，且不占标题行空间）。
  展开的入口在卡片**下方**一行「▸ 展开」—— 放在下面就不会和面板自己的刷新/时段按钮抢位置。
- **放不下时明说**：展开一张卡而那行没有空间时，走的仍是同一个 `attemptLayout`，
  于是照旧给出「放不下」的原因，而不是默默什么都不发生。
- 折叠状态和其余偏好一样只存在浏览器里（`dsh-hud:prefs`）。它躺在每个面板自己的 `layout[id]` 里，
  所以**不需要**升 `PREFS_VERSION` 就能前向兼容。

### 卡片里的图形化设置：点 ⚙ 就能改，不用去翻设置页

机器、服务、仓库三张卡以前**必须有数据**才有内容，而那些数据只能写进插件的
`panels.*` 配置里 —— 对一个「装了就想看」的 HUD 来说，这是最陡的一段台阶。
现在每张卡自己带一个 ⚙，点开就是一张表单，**改完立刻生效，不用重启、不用编辑 JSON**。

**一个组件，三张卡。** 表单在**外壳**里实现一次（`SettingsForm`），面板只**描述**自己有哪些字段：

```js
fields: [
  { kind: 'list',   key: 'volumes', label: '监控磁盘', detect: …, format: … },
  { kind: 'number', key: 'pollMs',  label: '采样间隔', min: 2000, max: 600000, unit: 'ms' },
  { kind: 'text',   key: 'gpuCommand', label: 'GPU 命令' },
  { kind: 'toggle', key: 'untracked', label: '统计未跟踪文件' },
]
```

于是「加一张能配置的卡」不需要再写一遍表单 —— 和卡片本身继承同一套标题、折叠、缩放是一样的道理。

**优先级是明说的，不是猜的：** 卡片里存的 > 插件设置页里的 > 面板默认值。
表单顶部那行小字会告诉你此刻是哪一层在生效（「这些值来自卡片（设置页的值已被覆盖）」），
**恢复为设置页的值** 一键退回上一层。这条优先级不是装饰：设置页里的值仍然完全有效，
所以「我在设置页里改了怎么没反应」有一个看得见的答案。

| 卡片 | 能配什么 | 检测按钮做什么 |
|---|---|---|
| **机器** | 监控哪些盘、探活哪些端口（带自定义名称）、GPU 命令、采样间隔、超时 |
**机器卡不再画「本地模型服务」那一块。** 它以前列出五个已知的本地模型服务端口和各自加载了哪些模型 ——
五行，于是这张卡比所有邻居都高，而一张高卡在 3 栏网格里就是不好搭。探活本身还在跑、也还在 ⚙ 里可配，
只是不画在这张卡上 —— 探活的结果仍然在 state 响应里，⚙ 里也仍然能改端口。
**采样间隔也从 8 秒降到 3 秒**：CPU/内存/磁盘都便宜，只有 `nvidia-smi` 在 Windows 上要花约 1 秒，
所以不是 1 秒，而且 ⚙ 里 2 秒到 10 分钟都能调。 列出**这台机器真实存在**的盘：Windows 逐盘符 `statfs` 探测（26 个字母全试，找不到就不出现），macOS 读 `/Volumes`，Linux 读 `/proc/mounts` 并过滤掉 tmpfs/proc |
**几个刻意的选择：**

- **值的类型由字段决定，不由宿主事后猜。** 端口在宿主里是**数字**，而输入框里是字符串 ——
  所以字段自带 `coerce`：`8080` 存成 `8080`，`not-a-port` **被拒绝并写出原因**，
  而不是悄悄写进去再被宿主的校验丢掉。
- **能修的错误保留，不能修的错误丢弃。** 一个写成 `http://127.0.0.1:80 80/health` 的目标会**留在列表里**
  （表单里还能改回来）；一个连地址都没有的空行会被丢掉。设置界面**默默吞掉你刚输入的东西**是最快失去信任的方式。
- **仓库的「监控列表」不走设置接口。** 它和偏好不是一类东西：加一个路径必须**校验它真的是个 git 仓库**，
  而「恢复为设置页的值」**不能**顺手停止监控你的仓库。所以它走 `/git/watch`，和 `pollMs` 走 `/settings` 分开存。
- **改完不强制重读整张卡。** 写操作本身已经把新值回显给表单了；再补一次整卡请求，
  只会让一个还没落地的请求跟着下一次挂载一起漂。晚一个轮询周期（机器 8 秒、服务 60 秒）看到新仪表，
  比留下悬空请求划算。

**测试分成两半，因为两半能证明的东西不一样：**

- **宿主侧**（`tools/test-host.mjs`，+54 项）：每个设置路由的读/写/重置、越界值被**钳制**而不是存进去、
  未知字段被丢掉、探测路由**不写入任何东西**、以及三个平台各自的磁盘探测器（Windows 用假 `statfs` 验证
  「26 个盘符都试过、只返回真实存在的」、Linux 用假的 `/proc/mounts` 验证伪文件系统被过滤、macOS 读 `/Volumes`）。
- **浏览器侧**（`tools/test-client.mjs`，+28 项，跑在一块**自己的根节点**上）：⚙ 只出现在有设置的卡上、
  表单打开/关闭、每个字段渲染的是**宿主回显的值**、每个字段都有标签、写入是**单字段补丁**而不是整个对象、
  端口被写成分数而不是字符串。

**这一轮在测试里踩到的一个真坑（值得写下来）：** 设置写入的 promise 在 `act()` 之外 resolve，
React 会把 `busy: false` 排进队列**并且不刷新** —— 于是「写入之后的每一次交互」都在点一张**所有按钮都禁用**的表单，
而禁用的按钮**收下一次点击，什么都不说**。我为此把断言删了一轮又一轮，还一度写下「这是 jsdom 的限制」。
真正的修法只有一行：**把等待包进 `act()`**。`setTimeout` 不行。

### 数据库卡：四个驱动、零运行时依赖，只读由**服务器**保证（SQL Server 除外）

**四个驱动，全部手写，零运行时依赖**（`node:sqlite` 随 Node 一起提供，另外三个是网络协议）：

| 驱动 | 怎么说话 | 只读由谁保证 |
|---|---|---|
| SQLite | `node:sqlite`，随 Node 提供 | **引擎**：只读文件句柄 |
| PostgreSQL | v3 线协议（`node:net`）+ SCRAM/MD5 | **服务器**：`BEGIN TRANSACTION READ ONLY` |
| MySQL / MariaDB | 握手 + `COM_QUERY` | **服务器**：`START TRANSACTION READ ONLY` |
| SQL Server | TDS：PRELOGIN / LOGIN7 / SQL_BATCH | **插件**：见下 |

### SQL Server：这张卡的唯一一处「我们保证」而不是「服务器保证」

**SQL Server 没有只读事务。** PostgreSQL 有 `BEGIN TRANSACTION READ ONLY`，MySQL 有
`START TRANSACTION READ ONLY`，SQLite 有只读文件句柄 —— 这三个都是**服务器**在拒绝写入。
SQL Server 最接近的东西是 `ApplicationIntent=ReadOnly`（可用性组的**路由提示**，不是强制）
和只读**登录名**（那是用户在自己服务器上的决定，插件替他做不了）。

所以这个驱动的只读是**在这里**保证的：插件拒绝发送它判定为写的语句，而卡片上写明这一点 ——
`readonly: 'client'`，不是 `'engine'`，也不是 `'transaction'`，因为这三者不是一回事。
卡片上的锁形标签也会跟着变：三个服务器保证的驱动显示「只读 · 服务器保证」，
SQL Server 显示「只读 · 插件拦截」，鼠标悬停给出原因。

**这不是把话说小，而是把话说准。** 一个「只读」标签如果分不清「服务器会拒绝」和
「我们不会发送」，那它就是在借别人的保证。

### 密码：卡片直接收，凭据库存，不写进设置文件

**（后续：这一版之后还有一次「填了密码仍然连不上」。）** 原因是 `withSession` 只认得 `resolve`，
而表单发的是 `{ secrets: { password } }` —— 这个选项被**静默丢弃**，驱动于是完全没收到密码，
回答「服务器要求 SCRAM-SHA-256 密码，但没有可用的凭据（在设置里填凭据名）」：
**一个看起来像凭据问题的错误，其实是一个参数没传下去。** 错误信息现在同时指出两条路
（连接表单里填密码 / 设置里填凭据名），而「字面密码优先于解析器」这条规则写在 `withSession` 里，
并有断言钉住：字面密码能登录、按名字解析能登录、错的密码仍然被拒。


**「凭据无效」是一个表单设计错误，不是安全设计错误。** 之前的连接表单只收凭据的**名字**，
值要去 DSH 凭据库里找 —— 存储规则是对的（密码不该进设置文件），但表单是错的：
**刚打完用户名和密码的人，不应该被告知「凭据不存在」。**

现在表单收密码本身，流程是：

1. 密码**随测试请求一起**发出去（不再先去查凭据库）；
2. 测试**通过之后**才写入 DSH 凭据库，名字留空就自动生成 `dsh-hud-sql-<id>`；
3. 存进设置文件的连接**只有这个名字**；
4. 连接成功的提示会写明「密码已存入凭据 xxx」—— 一个消失在看不见的地方的秘密，下次还会被再打一遍。

**测试直接读请求体来验证第 3 条**，于是抓到了一个真的泄漏：`saved` 曾经是 `{ ...draft }`，
而 draft 里带着刚输入的密码 —— 也就是说 `"password":"sup3r-s3cret"` 会被写进磁盘上的设置文件。
这正是凭据库存在的意义，而它差一点就绕过去了。现在按名字摘掉：`const { password: _typed, ...withoutSecret } = draft`。

### 多个连接：能增、能删、能改 —— 以及原来那样为什么不算「能」

存多个连接的能力一直都在（`connections` 是个数组），但**管理**它的界面是这样的：
一行小圆片选连接，后面跟着**另一行** `×` 按钮。于是屏幕上三个连接就有三个 `×`，
**第三个 `×` 属于第三个圆片，靠的是数数**；而「修改」只有一条路：先把某个连接切成"当前"，
再改「那个连接」—— 共享设置表单只认得一个对象。功能都在，但没有一个是安全的。

现在是一行一个连接，每行带着自己的按钮：

| | 行为 | 为什么这样 |
|---|---|---|
| **增** | `＋ 新建连接` 打开编辑器，**先测试**，通过了才写进设置 | 「连接」按钮写进去一个连不上的连接，是在骗人：条目出现了、卡片看起来配好了、之后每次都失败 |
| **删** | 点删除先问一句，凭据**默认保留**（要删得单独勾） | 一个凭据可能被两个连接共用（同一个库、一个只读一个可写），删掉一个连接不该悄悄弄坏另一个。宿主那边也会拒绝：只要还有连接在用这个名字就不删 |
| **改** | 点某行的「改」，编辑**那一行**，保存**原地替换**、且**不切换当前连接** | 顺序是人排的（编辑后跳到末尾就是另一个列表了）；而且「在用哪个」和「列表里有哪些」是两个决定 —— 改备用连接的错别字，不该把你正在查询的连接换掉 |
| **复制** | 复制一份，设置和凭据都沿用，只换 id 和名字 | 同一个库的「只读 / 可写」两份配置是最常见的重复劳动 |

**还有三件它故意不做的事：**

- **不在你打字时保存。** 编辑器是**草稿**：不点保存，设置文件一个字节都不动。
  被它替换掉的共享表单是每次按键都写盘的 —— 对一个城市名没问题，对一个数据库主机名
  就是「打了一半的 `10.0.0.` 成了这个连接的 host」。
- **不隐藏坏掉的连接。** 凭据被删掉的连接，会在**行上**标出「凭据缺失」（宿主读一次凭据库就能回答），
  而不是等你点进去、等一句「凭据 xxx 没有找到」——多个连接时，「哪个是坏的」正是这个列表要回答的问题。
- **不靠禁用按钮来「警告」。** 没测试过也能保存（服务器只是暂时不可达时，不该把人锁在门外修不了错字），
  但按钮上写的是**「未测试，仍要保存」**：警告写在标签上，不藏在规则里。

**测试（浏览器侧新增 37 条断言，宿主侧 11 条）钉的是行为，不是长相**：一个有 12 个连接的假宿主、
一个会**记住写入**的 fixture（真宿主会落盘，下次轮询读回来 —— 不这样，断言就成了在测 fixture）、
以及每一条都问「发了什么」：改的是**被点的那一行**而不是当前连接、保存**原地替换**、
删除**只删被点的那一个**、删完 `active` 还指着一个存在的连接、密码**只**进凭据库（设置文件的请求体里
不许出现它）、同一个凭据在别的连接还在用时不删。

**布局是截图看的，不是猜的**：`dsh-hud-acl-recovery/repro/connections.html` 用**面板自己的 CSS**
搭出这个管理器，在 480px 宽的 Edge 里截图 —— 第一版就抓到了「删除确认」那一行**溢出**、
`取消` 被卡片边缘切掉（确认块现在独占一行）。

### 顺带修掉：SQL Server 的默认端口是 3306

`cleanProfile` 里写的是 `driver === 'postgres' ? 5432 : 3306` —— 这个"不是 postgres 就是 MySQL"的捷径
让 **SQL Server 拿到了 MySQL 的端口**，于是连一台 1433 上的真服务器时，一个包都没发出去就被拒了。
现在每个驱动在自己的规格里声明 `defaultPort`，并有断言钉住四个值。

### SQL Server 的「登录超时」：两个各自都致命的 TDS 错误

**症状**：用户名密码都对，连一台真实的 SQL Server 2008 R2 时，卡片一直等到浏览器 20 秒的
fetch 上限，报「请求超时」；用 `sqlcmd` 连同一台、同一组凭据，**97 毫秒**就拿到真正的
「用户 'x' 登录失败」（SQL 18456）。也就是说服务器又活又快，**它只是不回答我们**。

抓包对照 Microsoft 自己的驱动（ODBC Driver 17 与老的 `{SQL Server}`）之后，问题有两处，
而且**各自都足以让服务器一声不吭地丢掉登录包**（不报错、不断连接，就是沉默 —— 这是最
难从外部定位的失败方式）：

| | 错在哪 | 为什么沉默 |
|---|---|---|
| **1. 登录包根本没加密** | 驱动只在服务器回 `ENCRYPT_REQ` 时才做 TLS。但 SQL Server 默认回的是 **`ENCRYPT_OFF`**，而它的含义不是"不用加密"，而是**"只加密登录包"** —— 这正是为什么 Microsoft 的驱动即使 `Encrypt=no` 也会把 LOGIN7 加密 | 服务器在等一个 TLS 握手，收到的却是明文 LOGIN7，于是它**忽略** |
| **2. 偏移量基准错了 8 字节** | LOGIN7 的可变字段偏移量是**从 LOGIN7 结构开头**（94）算的，代码写的是 `8 + 94`（把 TDS 包头算进去了） | 就算包加密了，服务器也认为这个登录包结构不对，同样**忽略** |

**第 1 条的三个细节**，缺一个都不行（都是抓包对着看出来的）：

- TLS 握手的记录必须**装在 TDS 包（type `0x12`）里**传，握手完成后才改为裸 TLS 记录 ——
  SQL Server 不接受裸的 TLS 握手（实测：直接 `tls.connect` 会被服务器断开）；
- 登录包加密**只覆盖 LOGIN7**：服务器随后用**明文**回复，所以握手完成后必须让 TLS 层
  **放开**这个 socket，否则回复会被 TLS 吞掉；
- 老服务器只提供 **TLS 1.0**，而 OpenSSL 3 默认拒绝它（要 `minVersion:'TLSv1'` +
  `ciphers:'DEFAULT@SECLEVEL=0'`）；另外 OpenSSL 默认会把第一条应用记录拆成一个空记录
  加一条真记录（BEAST 缓解），**Schannel 不这么做**，而服务器对拆过的登录同样沉默
  （`SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS`）。证书是 SQL Server 自签的
  `SSL_Self_Signed_Fallback`，登录包加密这一档不校验证书（和平台驱动一致），
  整条连接加密（强制 TLS）那一档才按开关校验。

**顺带修掉的两个"沉默"放大器**：连接和登录阶段**以前没有任何超时**，所以无论是端口没人听、
TCP/IP 没开、还是服务器不回答登录，表现全都是同一个「20 秒后超时」；现在两段各有超时，
并且报错会说清是哪一段、以及常见原因。

**测试也一起修了 —— 这才是它能活下来的原因。** `tools/fake-tds.mjs` 读 LOGIN7 偏移表时
**减了 8**，和驱动的错误假设完全一样：两个错误互相抵消，测试全绿而驱动是坏的。
现在这个假服务器断言规范自己的规则（`state.hostNameOffset === 94`），并且会说
**TLS 里的登录**和**明文登录**是两条不同的路径（`state.loginTransport`），
两条路径都有断言钉住。

真机验证（本机就有一台 2008 R2 可达）：修之前是 20 秒沉默，修之后 **56–139 毫秒**
拿到服务器自己的 18456 错误。

### 「登录成功，但结果全是错的」：第二轮，只有真服务器能查出来的解析错误

**登录修好之后，用它连真库，问题才真正开始暴露** —— 而且这一轮更危险，因为
**它们不报错，它们返回数字**：`select count(*)` 曾经一本正经地回答
`54324743469268992`。

这一轮的方法换了一个：**不看代码，看字节**。抓自己驱动与真服务器之间的明文会话
（登录之后的会话是明文的），把 `select cast(12.34 as decimal(10,2))` 的回复逐字节
对出来，然后照字节改解析器。清单如下，每一条都是量出来的，不是猜的：

| 类型 / 位置 | 真服务器实际发的 | 之前怎么错的 |
|---|---|---|
| **COLMETADATA 的字符列** | 长度后面还有 **5 字节 COLLATION** | 没读这 5 字节，于是列名和后面的 ROW 全部**提前 5 字节**被读 —— `select @@version` 报「不认识的 token 0x8c」，那正是这一行文本的第一个字节 |
| **INTN / BITN / FLTN / MONEYN / DATETIMEN / DATEN / DECIMALN / GUIDN** | 值前面是 **1 字节**长度 | 读成 2 字节，`count(*)` 的 `04` 被当成 4612 的前半段 |
| **TIMEN / DATETIME2N / DATETIMEOFFSETN** | 类型信息**只有 1 字节**（scale） | 读成 maxlen+scale 两字节，往后全错位（`select *` 的列名从第一个 datetime2 开始变乱码） |
| **DECIMALN 的值** | **符号字节 + 小端绝对值**：`12.34` = `01 d2 04 00 00`，`-0.50` = `00 32 00 00 00` | 先按「首位符号位」读成 `-47223664828696452124.62`，再改成二进制补码后又读成 `184467440737095515.66` —— **两种错法都能返回一个看起来像小数的东西** |
| **DATE 的纪元** | 第 0 天 = 0001-01-01 | `Date.UTC(1, 0, 1)` 在 JS 里是 **1901** 年（0–99 被映射到 1900+），于是 `2024-03-05` 显示成 **3924-03-05** |
| **`nvarchar(max)` / `varbinary(max)` / `xml`** | **PLP**：8 字节总长 + 若干「4 字节块长 + 内容」，以 0 长块结束 | 当成普通 NVARCHAR 读，于是向服务器要 65535 字节然后抛异常 —— **任何一张有 max 列的 `select *` 都会失败** |
| **GUIDN** | 类型信息里 1 字节 maxlen | 少读 1 字节，`select * from sys.databases` 的列名从 uniqueidentifier 那列开始变乱码 |
| **XML** | 类型信息里 1 字节「有无 schema」 | 当成列名长度读 |
| **TEXT / NTEXT** | 1 字节长度，0 表示 NULL | 走了通用可变长分支 |
| **MONEY / MONEYN** | 8 字节：**高 32 位在前**，各自小端 | 只读头 4 字节（永远是 0），而且**少读 4 字节**把后面全带偏 |
| **SQLVARIANT** | 行内长度是 **4 字节**，值是「类型 + 1 字节 + 值」 | 读 2 字节 |
| **ORDER(0xa9) / RETURNSTATUS(0x79)** | 有 `order by` 的查询一定带 ORDER token | 不认识的 token 直接让整个查询失败（`不认识的 token 0xa9`） |

**教训和上一轮一样，而且更狠**：`tools/fake-tds.mjs` 当时的 nvarchar **不带 collation**、
INTN 直接 1 字节长度混着来、decimal 写的是 64 位二进制补码 —— 假服务器比真服务器
"宽松"的地方，正好就是驱动出错的地方。**一个比真实协议宽松的假服务器，测出来的绿色是假的。**
所以这一轮的每一条都同时改了假服务器（带 collation、PLP、符号字节十进制），
并且新增了断言：混合类型的一行必须解成 `[[18,"甲","12.34","hi"],[0,"乙","-0.50",null]]`、
`order by` 不许失败。

**验证方式留在 `dsh-hud-acl-recovery/sqlserver/`**：`probe-types.mjs`（逐类型的字节）、
`probe-max.mjs`（PLP 与 sql_variant）、`probe-decimal.mjs`（十进制符号）、
`live-final.mjs`（对着真库跑一遍各种查询）。

### 第三轮：登录成功、查询成功，**表结构读不出来**

第二轮修完之后，卡片连上真库能查数了，但**列目录（表结构）**这一步报：

```
TDS: 不认识的 token 0x0（第 0 字节）
```

这句话本身就是线索：**「第 0 字节」**。一条正常的应答第一个字节一定是 `0x81`（COLMETADATA）
或 `0xfd`（DONE），`0x00` 说明解析器拿到的**不是一条完整的消息**。

抓包一看就明白了：`columnsQuery()` 的应答是 **22852 字节、6 个包** —— 而这是这个驱动
**唯一**会发出的大查询（`objectsQuery` 只有 1140 字节，一条语句一个包）。会话里的分包重组是这样的：

```js
onData(chunk) {
  const whole = Buffer.concat(this.buffer)
  const message = []                      // ← 每次 data 事件都新建
  while (…) {
    message.push(whole.subarray(at + 8, at + length))
    if (末包) { resolve(Buffer.concat(message)); return }
  }
  this.buffer = [whole.subarray(at)]      // ← 不完整的包留下，message 丢掉
}
```

**TCP 一次不会把 6 个包一起给你**，所以第一个事件里凑齐的几个包被 `break` 之后**扔掉了**，
下一个事件从"还在缓冲里的那几个包"重新开始 —— 消息缺了开头，解析器于是从一行数据的中间开始读。

修法是把 `message` 变成会话上的 `this.parts`（和登录那条路径里的 `readMessage` 一样，
它的 `chunks` 本来就在闭包里、跨事件存活 —— 所以登录一直是好的，只有会话这条有 bug）。

**假服务器也是同谋**：它把一个应答**整体塞进一个包**（长度字段是 16 位，塞得下），
于是"跨包应答"这个形状在测试里根本不存在。现在它按真服务器的 4096 字节分包，
并且有 `trickle` 选项把包分开送 —— 那正是出错的形状。

**这条测试是有牙齿的**：把修复撤掉再跑，它报的就是线上那句
`TDS: 不认识的 token 0x0（第 0 字节）`。另外查过其它五个驱动（pg/mysql/db2/oracle/sqlite）：
它们用的是跨事件存活的 reader，没有同一类问题。

### 第四轮：卡片显示「还没有连接」，而设置文件里明明有

用户看到的是「网络错误：signal timed out」+ 空列表 + 「0/12」，于是问：
**我的 SQL Server、PostgreSQL 配置怎么都没有了？**

**答案是一条都没丢** —— 设置文件里好好地躺着那条 SQL Server 连接（我给用户读过原文件），
凭据也在。真正发生的是：

1. 卡片读状态的那次请求**超时**了（浏览器 20 秒放弃）；
2. 页面刷新后卡片**从来没有拿到过快照**（`snapshot === null`）；
3. 而它把「没有快照」渲染成了**「空列表」** —— 两者在屏幕上一模一样，但一个是"读不到"，
   一个是"没有"。**这是这个卡片最不该犯的错**：它把"我不知道"说成了"没有"。

（历史也查清楚了：10:24 的备份里是一条 **PostgreSQL** 连接 `LingboPassport@127.0.0.1:5432`，
后来被替换成了 SQL Server 那条。这个存储**一次只存一条**，从来没有同时存在过几条。）

**超时的根因是凭据服务可能整个卡住。** `dsh-credentials-local` 把所有操作串在一个队列后面
（`await this.operations`），写文件时还要拿文件锁 —— **只要有一个操作永远不结束，之后每一次
`resolve()` 都会永远等待**。从卡片这边看，就是所有碰凭据的路由都不再回应。

所以这一轮改了三处，都是"依赖不回应时该怎么办"：

| 改动 | 之前 | 现在 |
|---|---|---|
| **凭据解析** | 服务不回应就永远等下去，卡片被拖死 | **5 秒上限**，超时**直接读 `$DSH_HOME/.credentials.yaml`**（和"服务不存在"走同一条兜底），面板照常工作 |
| **凭据写入** | 「写」没有上限 —— 而**新增连接**正好要写：测试通过之后卡在存密码那一步，浏览器 20 秒放弃，连接永远没被保存 | 同样 **5 秒上限**，超时**直接改文件**（原子替换）—— 这也是服务没有可写方法时的同一条兜底 |
| **语句超时** | 连接和登录一直有超时，**语句没有** —— 服务器接受了登录却不回答查询时，路由一直挂着，直到浏览器放弃，而卡片只能说「网络错误」 | 用连接自己的 `timeoutMs`（默认 20s，按合约夹紧），并说清是**哪条语句**没有回应 |
| **读不到状态** | 渲染成空列表；状态读失败在有结果时还被**藏起来** | 明说「读不到状态，所以这里看不到连接列表 —— **存好的连接没有被删除**」，刷新按钮可用；失败**总是**显示（陈旧数据配一句警告，好过陈旧数据看起来一切正常） |

**这四条都有断言钉着**，而且用的是真形状：一个**永远不 resolve** 的假凭据服务（`resolve` 必须落到文件）、
一个**永远不返回的 write**（`writeCredential` 必须落到文件，且不许等到超时之外）、
一个**收了语句但不回答**的假服务器（必须报出是哪条语句，且用的是连接的 6 秒而不是浏览器的 20 秒）、
以及**一个新挂载的卡片 + 失败的 state 路由**（必须说"读不到"，不许说"还没有连接"）。

### 第五轮：这张卡也可以是 SSH 客户端（同一时间只有一个）

卡片顶部现在有一对按钮：**数据库 | SSH**。切开之后：

* **整张卡就是 SSH 客户端** —— 数据库那一半**不渲染、也不轮询**（`collect` 根本不会被调用，
  所以它是 SSH 客户端时不会去开任何数据库连接）。"同时只能存在一个"是**渲染上的规则**，
  所以就用渲染来断言：切过去之后数据库那边的控件**不在 DOM 里**，反过来也一样；
* **切换不是删除**：两边的设置都留着，切回去连接列表还在（也有断言钉着）。

SSH 这一半能做的：主机列表（增 / 删 / 改 / 复制，最多 12 台）、三种认证
（**密码** / **密钥文件** / **代理与 ~/.ssh/config**）、执行一条命令并显示
**stdout / stderr / 退出码 / 耗时**，外加几个常用按钮（uptime、df -h、free -m、id）。
密码和其他驱动一样只写进 DSH 凭据库，主机里只留一个名字。

**它用的是系统自带的 ssh**（Windows 上是 `C:\Windows\System32\OpenSSH\ssh.exe`），
这是这个仓库里**唯一一处没有手写协议**的地方，理由写在 `lib/ssh/client.js` 顶上：
一个能用的 SSH 客户端要密钥交换、主机密钥签名校验、AEAD 包层、userauth、channel 和 exec，
任何一处差一点，结果都是"永远认证不上"而且无从查起。用系统 ssh 换来的是**你自己的**
agent、`~/.ssh/config` 和 `known_hosts` —— 终端里能连的机器，卡片里就能连。
它是不是存在，是**问出来的**（`available()`），和 `node:sqlite` 一样。

诚实的边界，也写在卡片上：

* **它是命令，不是终端**：没有 PTY，所以 `vim`、`top`、`sudo` 的密码提示在这里用不了；
  `systemctl status`、`docker ps`、`df -h`、`tail -n 50` 可以；
* **没有只读开关**，因为 shell 没有这种东西。数据库那边能承诺"不发写"，
  这里不能对"你让我跑的命令"承诺任何事 —— 假装有开关比没有更糟；
* 一切都**有上限**：连接超时、整体期限（远端命令挂住会被断开，并明说远端那条可能还在跑）、
  64 KB 输出上限、命令长度上限。

两处只有真机上才会暴露的细节：

1. **Windows 的 ssh 把自己的本地化消息打成八进制转义**：DNS 失败时到达进程的是字面的
   ASCII `\262\273\326\252\265\300…`，而不是任何编码的字节。所以 `decodeOutput` 要先把
   `\ooo` 还原成字节、再按 **GBK** 解码（严格 UTF-8 先试，失败再退 GBK），
   否则卡片上显示的就是一串转义符；
2. **`SSH_ASKPASS` 在 Windows 上必须是真正的 exe**（`.cmd` 不行：`CreateProcess` 不会执行批处理），
   所以 askpass 程序是 **`node.exe` + `NODE_OPTIONS=--require askpass.cjs`** ——
   预载脚本把密码打到 stdout，然后在 node 试图运行 ssh 传来的那段"脚本名"之前退出。
   密码**从不进命令行**（argv 里没有它，有断言钉着），只在该子进程的环境里。
   `NODE_OPTIONS` 不支持引号，所以路径不能加引号 —— 这是**实测**出来的，不是猜的。

**真机验证**（一台 Ubuntu，`198.51.100.20`，Windows OpenSSH 9.5p2 作为客户端）：登录、
`uname -a`/`uptime`/`id`/`df -h` 各约 300–580ms；不存在的命令回来 `exit 127` 加 stderr；
密码填错 4.4 秒回来 `Permission denied`。走**卡片自己的路由**（测试 → 存凭据 → 存主机 →
执行）也是一样：密码从凭据库读，请求里没有密码，四条命令全部 `exit 0`。

而第一件会遇到的事，是这一句：

```
No ED25519 host key is known for 198.51.100.20 and you have requested strict checking.
Host key verification failed.
```

它正确、安全，而且**没有告诉任何人那个能修好它的勾选框**。所以 `explainSshFailure` 把 ssh
自己的话翻译成**该做的动作**（主机密钥 / 密码不对 / 端口不对 / 网络不通 / 解析不了 / 认证次数太多
/ 握手被打断），文案是**照着一台真实机器上真跑出来的字符串**写的，不是编的。
卡片显示这个动作，原始 stderr 仍然留在下面的输出块里 —— 两句话各归各位。

### 第六轮：它得是终端，不是"一条命令"

一条命令回答的是"跑这个，把结果给我看"。用户要的是另一件事：`cd` 要留住、程序要能提问、
屏幕要是远端画的样子。所以 SSH 这一半现在有**两个**东西：

* **单条命令框**（原来的，保留）：一条命令，stdout / stderr / 退出码 / 耗时；
* **「打开终端」**：一个**常驻的登录 shell**。按键喂进去，终端的输出读回来，
  中间是**一个活的进程**，不是每条命令起一个。

**屏幕，不是日志。** 日志是把字节往后接；终端有格子、有光标，程序会覆盖它刚写的东西 ——
这正是 `less`、`top`、进度条和行编辑在日志里什么都看不见、在这里却正常的原因。
所以客户端有一个小的屏幕模拟器（`createScreen`），覆盖 shell 真正用到的那一小撮：
CR / LF / BS / TAB、CSI 的光标移动（`A B C D H f G d`）、擦除（`J K`）、SGR 颜色
（含 256 色与真彩色）、存/取光标（`s u`）、以及**被忽略而不是被执行的** `?…h/l` 模式设置。
还有 **OSC**：Ubuntu 的提示符每次都会发 `]3008;…`，把它当文本渲染的终端是不可读的。
滚动出屏幕的行进 scrollback，所以 `cat` 过的东西还能往回翻。

传输上有三处是**真机上才发现**的：

1. **`-tt`**：两边都要 PTY，这才有交互 shell、作业控制、颜色和提示符；
2. **远端 PTY 的尺寸必须"告诉"它**。网页这边没有本地终端可以量，ssh 报上去的是 `0 0`
   —— 实测的，`stty size` 就是这么答的。所以会话用 `RemoteCommand` 在远端先
   `stty cols … rows …` 再 `exec "$SHELL" -l`：第一次提示符就是对的尺寸，而且**不会像
   用户自己敲了这行**。修好之后 `stty size` 答 `30 100`；
3. **密码仍然走 askpass，不走 PTY**：`SSH_ASKPASS_REQUIRE=force` 让 ssh **即使有终端**
   也用 askpass，所以会话的 PTY 是给 shell 的，登录密码不出现在流里、提示里或回滚里。
   会话里的 `sudo` 提示是用户自己的事 —— 那个提示就是用来打字的。

轮询而不是长连接：面板到宿主本来就是请求/响应，多一套机制就多一样要维护的东西；
700ms 一次，用起来就是终端。输出是**带绝对偏移的环形缓冲**，所以慢一拍不会丢字节，
没人看也不会无限增长 —— 读的人落后太多时会被告知（`lost`），而不是看到一个有洞的流。

**真机验证**（同一台 Ubuntu，走卡片自己的路由）：`cd /tmp` 之后 `pwd` 答 `/tmp`、
`export CARD=interactive` 跨行还在、`cd /etc && pwd` 答 `/etc`、
`echo "user=$(whoami) pwd=$PWD"` 展开成 `user=<user> pwd=/etc`、`stty size` 答 `30 100`、
`read -p` 提问能被回答、Ctrl-C 到得了远端、断开后**没有残留的 ssh 进程**。

测试里有两条断言是这次专门钉住的：**回车发的是 `\r` 而不是 `\n`**（shell 等的是行终止符，
只发 LF 它会一直等下去），以及**OSC 序列必须被整段吞掉**。

### 第七轮：股市卡片里的「今日涨跌榜」

「股市」这张卡现在有三个视图：**自选 / 涨幅榜 / 跌幅榜**，各 20 行。榜单来自东方财富自己的
选股接口（`push2.eastmoney.com/api/qt/clist/get`，按 `f3` 涨跌幅排序，`po=1` 降序 =
涨幅榜，`po=0` 升序 = 跌幅榜），免密钥、UTF-8 JSON、同一个域名 —— 和这张卡其它数据同源，
所以它在这张卡里而不是另开一张。

**最关键的一处不是排序，是过滤。** 真接口的榜首第一屏是这样的：

```
N力勤   001246  65.09  +206.59%     ← 新股首日，没有涨跌幅限制
元道退  301139   0.91   -72.51%     ← 退市整理
```

两条都是真的，**都不是市场今天的涨跌幅**。一份"今日涨跌榜"用它们开头，回答的是另一个问题。
所以先按 `pz=60` 多取，滤掉 `N…`/`C…`（新股与次新）和含「退」的（退市整理），再取前 20 ——
并且**把滤掉几行写在卡片上**：一份悄悄少几行的榜单，是没人能核对的榜单。

每一行给的是：名次、名称、代码、最新价、**涨跌幅**（红涨绿跌）和**成交额** ——
没有成交额的百分比只是一个故事。行尾的「＋」是**加入自选并选中**一步到位，
因为这是看第二眼的唯一理由：看它自己的 K 线。榜单打开时自选和 K 线让位，20 行需要那个高度。

还有一句必须写在卡片上的话：**今天不是交易日**（国庆假期）。一份不说明这一点的榜单，
在假期里看起来就是实时数据。所以卡片读 `session` 并写明「沪深京 非交易日 —— 这是最近一个交易日的榜单」。
榜单只在被打开时才请求（那是一张扫过 5900 只股票的表，不是几个 secid），缓存按开市状态伸缩：
开市中 30 秒，收市后十分钟 —— 收盘之后的当日榜单**不会再变**。

**真机结果**（沪深京 5921 只）：涨幅榜 20 行（善水科技 +20.01%、康希诺 +20%、…），
跌幅榜 20 行（安达股份 -29.97%、*ST仕净 -15.9%、…），两边各滤掉 1 行；
第一次请求 257ms，第二次 1ms（缓存）。

### 第八轮：鼠标停在榜单某一行上，看它的当日分时

榜单回答「今天什么在动」然后就停住了 —— 下一个问题永远是「它长什么样」，而列表答不了，
选中标的的 K 线一次只能答一只。所以**行上悬浮，就画它自己当日的分时**。

三件事决定这是功能还是骚扰，每一件都有断言钉着：

1. **等待指针停稳**（160ms）才发请求。鼠标扫过二十行不该是二十次上游请求 ——
   这个接口是按 secid 真取一次数据的，一次悬浮发二十个请求的卡片会被限流。
   截图之外的断言是：**扫过三行，请求数 +0** ✓。
2. **客户端也有缓存，而且和宿主同一分钟。** 宿主给分时图一分钟寿命（`INTRADAY_CACHE_MS`），
   客户端 hover 缓存也是 60 秒 —— 两个缓存寿命不同，就会在没人能解释的地方打架。
   回到看过的行是**瞬间**且不再发请求（有断言）。
3. **它永远不接鼠标**：气泡是 `pointer-events: none`。会捕获指针的提示框会让底下的行在
   enter/leave 之间闪烁，这是这类功能最经典的翻车方式。需要点击的东西都在行上。

气泡**立刻**出现（先写「读取中…」再补图）：一个等网络回来才出现的提示框，在请求期间看起来就是坏的。
落地位置按视口夹紧（右边放不下就放左边，下边放不下就上移）。键盘用户一样有：行是可聚焦的，
`focus` 就是不需要鼠标的 hover。

**真机验证**（`period=realtime`，榜上的三只）：各 **240 根一分钟 K 线**，日期**只有一天**
（`2026-09-30`，最近一个交易日 —— 今天是假期），时间从 09:31 到 15:00，
最后一根的收盘价**就是榜单上的最新价**（301190 → 35.93 ✓，688185 → 102.64 ✓，920344 → 24.35 ✓），
数值完整；同样的请求再来一次 0ms（缓存）。

### 第九轮：一张太小的图，和「点开之后别收走」

第一版的悬浮图太小 —— 小到**图里面没有数字**：这张图把十字线读数画在自己的框里，
框太小就等于没有读数。而且它一离开鼠标就消失，看不了两秒。

所以 hover 和 click 现在是**两件事**：

* **悬浮 = 瞥一眼**：浮动小图（300×168，比原来大了一圈），跟着鼠标走，离开就收；
* **点击 = 看这个**：把它钉进这张卡本来就放 K 线的位置 —— **整卡宽、220 高**，
  足够让图自己的十字线读数看得清。钉住之后：
  * **鼠标移开不会收**（这就是全部的差别，有断言钉着）；
  * 表头写着**这一只、什么价、今天的高低与成交额**（「详细内容」直接写在上面，
    不用从蜡烛里读）；
  * **「关闭」** 收掉；**切换页签**（自选 / 涨幅榜 / 跌幅榜）也自动收掉 ——
    钉住的东西属于产生它的那个榜单，换了问题，答案就该跟着走；
  * 点另一行就换那一只；钉住期间不再弹悬浮小图（一次只看一张图）。

缓存两边共用：先悬浮再点击是**对同一只股票的一次注视**，向上游要两遍是只会在限流时才被发现的浪费。

### HUD 的高度可以拖

一直在变的 `--hud-max` 原本只能由测量决定：应用列高 − 标题行 − 留给输入框的余量。
这是对的**默认值**（输入框始终看得见），但它也是一条用户无法反驳的上限 —— 网格需要更多空间时，
唯一的出路就是卡片里的滚动条。

所以高度变成了一个偏好：**自动**（测量的结果）或**一个数字**（在 HUD 底边拖出来）。
它被**故意允许超过列高** —— 把输入框顶到屏幕外、让**页面**滚动而不是卡片滚动，是你对自己屏幕的决定，
也是十二行网格唯一能完整看到的办法。双击或按 Home 恢复自动，标签会写明你正在哪一种状态里。

键盘同样可用（`role="separator"`，方向键 20px，PageUp/PageDown 一整行，Home 回自动）——
一个只有鼠标能用的手柄，对键盘用户就是不存在。

**拖拽只注册一种事件**：`POINTER_EVENTS ? onPointerDown : onMouseDown`。浏览器为一次按下
同时发 `pointerdown` 和 `mousedown`，早先的版本两个都注册了，于是每个位移都被应用两次、
卡片在鼠标第一次抖动时就冲到最大值。这条教训写在代码里。

### TDS 协议里踩到的两个坑（都写进了测试）

1. **PRELOGIN 的选项表是**大端**，而 LOGIN7 的偏移表是**小端**。** 同一个协议里两张表、
   两种字节序。我用公用的（小端）读取器去读 prelogin 表，两个偏移都变成 ~2816，于是每个切片都是空的。
   唯一的症状是版本号显示成 `undefined.undefined.undefined` —— 正是那种会在日志里被忽略的东西。
   更糟的是**加密字节也来自那个空切片**，值是 `undefined`，而 `undefined === ENCRYPT_REQ` 是假，
   也就是说：**一台强制 TLS 的服务器会被用明文应答。** 现在这一条有断言钉住。
2. **LOGIN7 的偏移是从包头算起的**（包含那 8 字节），而假服务器拿到的是去掉包头的负载。
   驱动写对了、假服务器读错了 —— 两边不一致时用户名变成乱码，正好说明这条规则是真的。

测试用 `tools/fake-tds.mjs`：它**按真实服务器的方式读** PRELOGIN 和 LOGIN7，并且用一份
**独立实现**的规范变换把密码解混淆 —— 所以「密码正确地到达」是关于驱动的事实，
而不是关于我自己想法的自证。密码混淆本身也对着规范算术断言（`'a'` → `0x61 0x00` → `0xB3 0xA5`）。

**没做、并且明说的**：Windows / AD 认证（需要身份提供方的令牌，不是凭据）、MARS、
以及完整的 TDS 类型系统（常见类型正确解码，冷门类型显示为 `<type 0xNN>` 而不是猜一个值）。
### GitHub 卡：CI 状态与「等待我评审」

在原有事件流之上加了两块，**复用已经存好的 `GITHUB_TOKEN`，不需要任何新凭据**：

- **每个仓库一行 CI**：默认分支上最新一次 workflow 的名字、结论、分支、多久之前；
  多个失败 / 进行中时补上计数。
- **等待我评审**：`is:pr is:open review-requested:@me` 的结果，带仓库名、标题、草稿标记与时间。
- **徽章改成「需要人的事」**：未读事件 + 待评审 PR + 失败流水线。三者都容易被错过，
  一个数字把它们放在一起。

用真 token 实测（`DSH_HUD_LIVE_HOME` 指向真实 profile）：

```
github  ok  signed in as <you> (4 public repos) · 待我评审 0
            · 监控 2 个仓库，其中 2 个带 CI 数据 · CI 失败 0 / 运行中 0
```

三个刻意的判断，都有实测依据：

| | |
|---|---|
| **`conclusion: null` 不是失败** | 真实响应里正在跑的 run 就是 `status: in_progress, conclusion: null`（拿真 token 抓到的第一个 run 正是如此）。写成 `conclusion !== 'success'` 会把**每个正在跑的构建报成坏的** —— 而一个总在报警的 CI 徽章，最后只会被忽略 |
| **`review-requested:@me` 需要授权** | 未登录时它返回 **422，不是空列表**。所以搜索失败必须当成错误显示，否则卡片会把「查不了」显示成「没有待办」—— 而这两件事的含义正好相反 |
| **「0 次运行」也是一种答案** | 该 profile 的两个仓库都不使用 Actions，`total_count = 0`。卡片显示「没有 CI 记录」，既不是失败，也不是功能缺失 |

**这一轮又抓到一个自己的 bug，而且只有在线自检抓得到**：`decorated` 投影只列出它认识的字段，
于是 CI 数据**被静默丢掉** —— 面板刚取回的数据在 payload 里根本不存在。在线自检因此报出
「2 个仓库，0 个带 CI 数据」，而请求其实完全成功。修法是把 `ci` 纳入投影，并把规则写进注释：
**没被列出的字段会被丢掉**。

顺带修掉一个更根本的不对称：`writeCredential` / `removeCredential` 在服务不可用时会去改
`$DSH_HOME/.credentials.yaml`，而 `resolveCredentialValue` **只问服务** —— 于是 token 可能被写进去，
却对写它的那个面板不可见。现在读也有文件兜底（真实 profile 的在线自检一直显示「not signed in」，
根因就是它）。三条路径现在对称，各有测试。

### 空气质量（挂在天气上）与汇率（挂在股市上）

两个都是**既有卡片的字段，不是新卡片** —— 它们本来就该和旁边的数字一起看。

**空气质量**用 Open-Meteo 的空气质量接口（与天气同源、同样免密钥，所以没有第二个供应商要信任、要失败）。
标题栏显示 `AQI 84 良`，展开后是 PM2.5 / PM10 / 臭氧 / 二氧化氮 / 二氧化硫 / 一氧化碳。

- 等级用 **EPA 的六档**，因为 `us_aqi` 就是这个定义：优 / 良 / 轻度污染 / 中度污染 / 重度污染 / 严重污染。
  颜色点和**文字**始终一起出现 —— 一个绿点配「重度污染」比没有颜色更糟。
- 只请求**确实存在**的字段：写了一个只属于预报的变量（`pm2_5_albedo`），接口回 **400 + 空 body**，
  第一版就是这么失败的。
- 天气、预警、空气是三次**独立的** `Promise.allSettled`：空气接口挂了只多一行原因，
  **不会**把温度一起带走。

**汇率**用股市卡已经在用的 `push2.eastmoney.com`（零新依赖、零新凭据），一行显示
`USD 6.7186 +0.14%  EUR 7.5891 -0.18%  GBP …`，其中日元那一项标了「反向」（它是 CNH→JPY）。

| | |
|---|---|
| **精度来自数据本身** | 用响应里的 `f1`（小数位数）算 `f2 / 10^f1`，而不是写死 `/10000` —— 写死今天全对，某个品种改精度的那天就全错 |
| **secid 是查出来的，不是猜的** | `m:133` 是 eastmoney 的**离岸人民币**板块。猜 `119.USDCNY` 之类**不会报错**，只会返回一行 —— 第一版看着「能用」，其实只有一个汇率 |
| **反向报价要标出来** | `CNHJPY` 是「1 离岸人民币 = 23.5 日元」，不标就会被读成「1 日元 = 23.5 元」 |

在线自检覆盖了两处，并且**检查量级**：`USD/CNH` 必须在 3–15 之间，
因为精度算错时不会报错，只会把 6.7 变成 67180 或 0.0006。

```
weather  ok  无锡市/江苏 阴 22.2°C 湿度73% 风10.1km/h · 空气 AQI 84（良）PM2.5 27.1 PM10 39
market   ok  7/7 priced · 上证指数 3842.19 0.31% · 汇率 USD 6.7193 / EUR 7.5894 / GBP 8.8844
```

**这一轮发现的真 bug（测试抓到的，不是我看出来的）**：`Number(null)` 是 `0`，
所以**缺失**的 AQI 会被判成「优」—— 等于给没拿到的数据发一张「空气极佳」的证书。
现在 `null` / 空串 / 非数字一律**没有等级**，而不是默认等级。

### 两张卡片被删掉了：服务与仓库

**服务卡和仓库卡已从代码里删除**，不是关掉。两张卡都从未被配置过，而一张永远是空的卡片
是注册表、设置页和文档里的噪音 —— 删除才是诚实的版本。宿主半区一起删，路由就真的不存在了，
而不是留下一堆没人读的空接口。留在磁盘上的只有它们的状态文件
（`storages/dsh-hud/services` 与 `.../git`）—— 惰性数据，写在这里而不是悄悄删掉。

**测试里保留了「它们确实不在」的断言**（宿主侧查路由表，浏览器侧查注册表与胶囊），
这样一张卡片不会在某轮里悄悄长回来而没人注意。

### 这一轮挖出的一个长期潜伏的 bug

线索最初来自服务卡（那张卡后来被删掉了），但 bug 与它无关 —— 它影响**每一个**面板：

live-check 报出 `请求超时（[object Object] ms）`，追下去发现是**两件叠加的事**：

1. **`resolveSchemastery()` 从来没读过注入的工厂。** 工具脚本一直在设
   `globalThis.__DSH_HUD_TEST_SCHEMASTERY__`，而 kit 从没读它 —— 于是 `mod.Config` 是 `undefined`，
   在线自检里**每个面板一直在跑默认值**。这就是"配置好的 targets 传进去是空的"的原因。
   现在注入的工厂排在第一优先级（并写明了为什么）。
2. **`unwrap` 不会展开嵌套的 schema 节点。** `new Config({…})` 里凡是你没写出来的字段，
   拿到的不是值而是**节点**（一个带 `type` + `meta` 的对象）。面板读 `config().timeoutMs` 以为拿到数字，
   实际拿到对象，字符串化就成了 `[object Object] ms`。

修法不只是改工具：`panelConfig` 现在**只把纯数据交给面板**（节点被丢弃），并且**会说出来**——
丢掉的键会经 `apply()` 打日志。一个被静默忽略的设置项，正是这个工程拒绝交付的东西。
两条都有测试钉住：`a schema node is dropped, not passed through as data`。

### 机器卡：唯一一张永远有数据的卡

别的面板都在等别人的服务器。这张只依赖 `node:os`、`node:fs` 和（有的话）`nvidia-smi`。

本机实测（`tools/live-check.mjs` 打印真值）：

```
machine  ok  CPU 22.7% · 内存 86% · 磁盘 2 (C: 167 GB 可用, E: 92.3 GB 可用)
             · GPU NVIDIA GeForce RTX 3060 Laptop GPU 0/6144 MiB · 本地服务 0/5
```

诚实的地方都是刻意的：

| | |
|---|---|
| **CPU 是速率，不是平均值** | `os.cpus()` 给的是**累计** tick。第一次采样没有前值就返回 `undefined`，卡片显示 `--`。把"开机以来的平均占用"当成当前占用，会让一台闲了一周的机器永远显示 50% |
| **Windows 的 load average 直接省略** | Windows 永远返回 `0 0 0`。打印 `load 0.00` 就是撒谎，所以字段不存在，卡片写明原因 |
| **没有独显不是错误，是一种状态** | 没有 `nvidia-smi` 时 `gpu` 带 `error` 说明原因，而不是画一根 0% 的进度条冒充"空闲" |
| **本地服务「未运行」照实说** | 5 个端口全关着也是有效信息 —— 这行同时就是"你还能启动哪些"的清单 |
| **并发采集** | `nvidia-smi` 在 Windows 上约 1 秒。串行采集一次要 **1597 ms**，并行之后 **363 ms** —— 在 5~8 秒的轮询间隔下这是能感觉到的差别 |

`gpuCommand` 可配置（没卡时它只是不会成功）；`ports` 与 `volumes` 是 volatile 的，对着卡片就能改。

**这一轮又抓到一个自己埋的坑**：`buildConfig` 里每个面板的 `schema()` 是 `try/catch` 的 —— 这是对的
（一个面板的 schema 坏掉不该让所有面板都没有设置页），但**静默**的 catch 让机器面板因为少了一个
`import { live }` 就整个从设置页消失了，控制台一句话都没有。现在失败会被记下来、`apply()` 会打日志、
`tools/test-config.mjs` 会断言「每个声明了 schema 的面板都必须在设置树里」—— 这才是真正抓住它的那一步。

### 原生下拉的配色：`color-scheme` 不是 `color`

邮箱的「服务商」下拉一打开就是**浅底浅字**，什么都读不出来 —— 而页面上其它地方配色完全正常。

原因不在我的 CSS：**原生 `<select>` 的弹出层不是网页画的**，它是平台按元素的 **`color-scheme`** 绘制的，
跟你在 CSS 里写的 `color` / `background` 没关系。宿主用**自己的令牌**实现暗色主题（标记在 `body[data-ds-dark-theme]`），
画布声明的 `color-scheme` 和实际调色板**可以不一致** —— 于是弹层是亮的、而我的文字是给暗色调的。

两条修法，都做了：

| | |
|---|---|
| **不再用原生下拉** | 自己写 `TdSelect`：按钮 + 主题化列表（`--hud-pop` 实底、`--hud-line-2` 细线、选中项蓝底加粗）。它由**同一套令牌**染色，所以永远和卡片一致。行为照旧：点击/回车打开、方向键移动、回车选中、Esc 关闭（`stopPropagation`，不会连带关掉外层弹层） |
| **剩下的原生控件也修** | `color-scheme` 在挂载时**从实际绘制的表面令牌反推**并写到 `.td-root`：把 `--dsw-alias-bg-layer-1` 涂到一个探针元素上，读回计算色、算亮度、判断明暗。这样 `<input type="time">` 的选择器、滚动条、以及未来任何原生控件都跟着调色板走 —— 连第三方主题覆盖也一并跟上 |

测试直接把这条路封死：**整个待办面板里不许存在 `select` / `option`**（`querySelectorAll('select, option').length === 0`），
外加下拉的完整行为断言（开、列全、选中态、选完改表单、Esc 只关自己）。

### 邮箱：手写 IMAP，因为要的东西很小而协议很稳

`lib/imap.js`，**零依赖**：登录 → `SELECT` → 只读最近 N 封的标题 → `LOGOUT`。

- **用的是「授权码」不是账号密码。** 163 / 126 / QQ / 阿里 / 腾讯企业邮都拒绝账号密码走 IMAP，
  必须在网页设置里开启 IMAP 并生成授权码。登录被拒时，错误信息会**直接指向这一点**，
  而不是报一个 `AUTHENTICATIONFAILED`。
- **`BODY.PEEK`**：读信**不会**把邮件标成已读。
- **不猜哪封是可执行待办** —— 没有可靠信号，猜错就是把垃圾塞进别人的清单。列出最近邮件，点一下加为待办。
- 主题解码覆盖 RFC 2047：Base64 与 Q 编码、UTF-8 与 **GBK**（`=?GBK?B?…?=`），
  以及**跨折行的编码字**（RFC 2047 §2 要求去掉折行处的空白，中文长主题正好折在那里）。

**这里踩到并修掉的两个真 bug**，都是测试抓出来的：

| | |
|---|---|
| **字面量按字节，不按字符** | IMAP 的 `{n}` 是**字节数**。我原来按 JS 字符串下标跳，于是**任何含中文的信头都会跳过界**，把后面的 tag 行一起吃掉 —— 表现是**客户端永久挂起**（不是报错）。现在整条会话按 `Buffer` 走字节。 |
| **`removeCredential` 的偏见** | `writeCredential` 优先用 credentials 服务，而 `removeCredential` **永远**直接改文件。于是"退出登录"看似成功，服务里缓存的那份**还在** —— 测试里 `hasSecret` 退出登录后仍为 `true`。已改成对称优先服务方法。 |

### 飞书 / 钉钉：登录换 token

标准授权码流程，三个路由：`login`（保存 + 返回授权页 URL）→ `callback`（厂商把浏览器重定向到这里，
本机完成登录）→ `tasks`（用 token 拉待办）。token 与 client secret 都存进
`$DSH_HOME/.credentials.yaml`，**绝不进面板的状态文件** —— 状态接口会被卡片读回去。

服务商差异做成**数据表**（`LOGIN_PROVIDERS`），不是代码分支：飞书用 `app_id`/`app_secret`，
钉钉用 `client_id`/`client_secret` 且要多一个 `prompt=consent`。

**一句必须说清楚的话，界面里也写着**：插件**不能替你创建应用**，也不能替你通过企业审批 ——
没有 client id 就没有登录。回调地址填 `http://127.0.0.1:19387/dsh-hud/todo/callback`，
厂商是否接受本机回调取决于它的策略。接口路径按当前文档预置、可在界面上改；
如果租户返回的字段不同，`tasks` 会把**原始响应**显示出来，而不是假装成功。

### ICS 解析到哪一步（以及超出部分怎么处理）

手写，因为格式本身很小，依赖比解析器还大。支持真正会用到的部分：

- **折行**（RFC 5545 §3.1：以空格/TAB 开头的行是上一行的续行）
- `DTSTART`/`DTEND` 的三种形态：`VALUE=DATE`（全天 → **09:00**，不是午夜）、`...Z`（UTC）、`TZID=…`
- `VEVENT` **和** `VTODO`（后者**经常只有 `DUE` 而没有 `DTSTART`** —— 早期版本因此把它整条丢掉了）
- `RRULE` 限定子集：`FREQ=DAILY|WEEKLY|MONTHLY` + `INTERVAL`/`COUNT`/`UNTIL`/`BYDAY`（周）

**超出子集的规则是"报告"，不是"悄悄丢掉"**：无法展开的规则（`FREQ=YEARLY`、`BYSETPOS` 等）会保留它在区间内的
第一次出现、标记 `approx: true`，并在订阅状态里列出**具体哪个规则**没展开。上面那个 iCloud 订阅就诚实地
报出 `unsupported=["FREQ=YEARLY"]`。

时区用 `Intl` 反解偏移并**算两遍**（第一次猜测可能落在夏令时切换的另一侧）—— 提醒里差一小时，是那种
"不出事就永远发现不了"的 bug。实测同一面墙钟三个时区：`上海 14:00→06:00Z`、`纽约 14:00→18:00Z`（EDT）、
`伦敦 14:00→13:00Z`（BST）。

### 通知：1 小时 / 半小时 / 5 分钟，以及 16:30

**宿主只发布时刻表，浏览器负责响** —— 宿主没有用户听得见的时钟。分工和别的面板一样：宿主管数据，
浏览器管"用户的这一刻"。

| | |
|---|---|
| **提前量** | `leads` 默认 `[60, 30, 5]` 分钟，可改 |
| **只响最近的那一个** | T-30 时**只响半小时**那条（1 小时那条一小时前就该响过了）；T-5 时只响 5 分钟那条。**一次全响**是"打开页面就被三条通知糊脸"，也是人们关掉通知的方式。实测：一个在 T-20 才添加的待办，**只响一条**（半小时） |
| **不重复** | 每次触发记进 `localStorage`（`<id>@<提前量>`），刷新页面不会重播；一周前的记录自动清理 |
| **下班前** | 默认 **16:30**，每天一次，**只在明天确实有事时**才响（"如果有"），并且带 `day` 字段保证当天只响一次 |
| **两种呈现** | 系统通知（需你点一下授权）+ 标题栏上的一枚提醒胶囊（点它打开清单并清除） |
| **诚实的限制** | **页面必须开着**。关掉 Harness 就没有任何东西在跑 —— 这条限制在界面上也写出来了 |

### 番茄钟：时钟在宿主，响铃复用同一条链路

挂在待办面板的最上方（打开浮层第一眼就是它）—— 那里本来就放着你该做的那件事。

**计数来自两个时间戳，不是递减的计数器**：`startedAt` / `endsAt`，暂停时是 `remainingMs`。
所以刷新页面、卡片被隐藏、笔记本睡了一觉、Harness 重启，都**接着同一段**继续，
两个标签页看到的也是同一秒，而不是各自数各自的。浏览器只负责**画** `endsAt - now`，从不拥有已流逝的时间。

| | |
|---|---|
| **切换是惰性的，这是故意的** | 没人看的时候什么都没跑，所以隔夜结束的一段会在下次读取时结算 —— 结算成**一次**切换，而不是本可以发生的十一次。番茄钟**不可能**诚实统计没人在场的时段，编出来正是这个项目拒绝打印的那种数字 |
| **跳过得不到计数** | 跳过是"这段没做完"，不是"这段做完了"。测试钉住了这一条 |
| **重置保留今天的计数** | 计数是发生过的记录，不是计时器的一部分 |
| **第 4 段之后是长休息** | `longBreakEvery` 默认 4，长休息 15 分钟；每一次切换都带 `cycleId`，所以卡片能分清"新的一段"和"还是这一段" |

**响铃复用已有的通知链路**：宿主在响应里给出 `justEnded`（谁结束了、晚了多久、下一段多长），
卡片发一条**标题栏提醒胶囊**（和待办提醒同一个 `.td-alert`）+ 一条系统通知，
并写进**同一个 `localStorage` 台账**（键 `pomodoro@<cycleId>@<结束时刻>`），
所以同一段结束**不可能被播报两次** —— 缓存过的响应、重新渲染、两个标签页都不会。

在线自检跑完整一轮（`start → pause → resume → skip → reset`，外加未知动作被拒、设置生效）：

```
todo  ok  GET /dsh-hud/todo/state    open=0 leads=[60,30,5] 下班提醒=16:30 · 番茄钟 work 25分钟 今天0/25分钟一段
todo  ok  POST /pomodoro             start→pause→resume→skip→reset 全部通过 · 跳过不计入完成数 · 未知动作被拒 · 设置 30/6 生效
```

**一处自己发现并改掉的设计错误**：第一版把到点提示写进浮层内的 `notice`，
而 `.td-alert`（标题栏提醒胶囊）才是"不开面板也能看见"的那条线 —— 一段专注结束如果只有打开面板才看得到，
那它就不算提醒。现在用的是同一条提醒线。

### 三条被测试钉住的规则

```
ok  31 分钟外只有 1 小时那条是"当前的"          ← 迟到的提醒仍然有用，且只响一次
ok  所有提前量都过了，只响最近的 5 分钟那条
ok  T-20 才添加的待办只响一条，不是三条
ok  已经响过的提前量不会重响，刷新页面也不会
ok  下班提醒在没有明天事项时完全不出现
ok  同一面墙钟在三个时区落在三个瞬间
ok  只有 DUE 的 VTODO 不会被丢掉
ok  COUNT=6 的每周规则恰好展开 6 次
ok  超出子集的规则被报告，且标记为"近似"
```

## 高度：用**测量**，不用猜

dock 槽位在宿主里渲染在哪里？这决定了 HUD 能有多高。答案在应用自己的样式表里
（`tools/probe-app.mjs` 能直接从 `app.asar` 里读出来）：

```css
.composerStack{--dsh-composer-stack-gap:6px;flex-direction:column;display:flex}
.composerSeat{flex:none;display:flex}
/* 结构：composerStack = [ …dock 条目…, inputBar ] */
```

也就是说 **HUD 和输入框在同一个 flex 列里** —— 槽位文档写的也是
"Full-width entries **above the composer card**"。**HUD 多占一个像素，输入框就少一个像素。**

所以高度上限**不能是常数**（我原来写死 `100vh - 140px`，那是猜的）：

- 向上找到最近的**可滚动祖先**（聊天滚动区），量它的 `clientHeight`：
  ```js
  available = scroller.clientHeight - headRow.offsetHeight
  root.style.setProperty('--hud-max', `${available - COMPOSER_RESERVE_PX}px`)
  ```
- `COMPOSER_RESERVE_PX = 88`（**留给输入框的**：输入卡本身约 52px，其余是余量）。
  原先实测得出 104，后来降到 88：默认布局变成四行之后 HUD 需要更多竖直空间，
  而 88 仍是输入框高度的 1.7 倍 —— 让它紧一点，而不是让 HUD 一来就滚动。
- `.hud-body{max-height:var(--hud-max, calc(100vh - 210px))}`：卡片再高也**在 HUD 内部滚动**，
  而不是去挤输入框、或者把标题栏顶出裁剪区。
- `ResizeObserver` + `window.resize` 重新测量；两者在 jsdom 里都不存在，所以都有兜底。

这一条同时解决了前面两个症状的**共同根因**：HUD 与输入框抢同一列空间。

`tools/probe-app.mjs` 是为此写的只读探针（`list <路径片段>` / `grep <路径片段> <正则>`），
直接从 `app.asar` 读宿主源码 —— 普通 Node 读不进 asar，它自己解包。以后再问"宿主给我多少空间"，
用它，不要猜。

## ⚙ 布局编辑器：浮层，而不是文档流里的一块

原来它是**在文档流里**夹在标题栏和网格之间的一个块。HUD 一高，它就**把标题栏顶出屏幕** ——
连同那个用来关闭它的 ⚙ 一起顶出去，于是**关不掉了**（用户实际遇到的情况）。

现在它有三重保障：

| | |
|---|---|
| **① 浮层** | `position:absolute;top:calc(100% + 6px);right:0`，挂在标题栏内部。**打开它不会让 HUD 高一个像素**，⚙ 就停在原地 |
| **② 自带高度上限** | `max-height:min(62vh,440px)` + `overflow-y:auto`。视口再矮也是**在它内部滚动**，不会被切掉；标题栏那条（含已用栏位和关闭按钮）`position:sticky` 钉在滚动区顶部 |
| **③ 三个出口** | ⚙ 再点一次 / 面板内的 **✕** 关闭按钮 / **Esc** / **点外面**。任何一个都不依赖 ⚙ 是否在屏幕上 |

另外把**卡片网格**本身也加了上限（`max-height:calc(100vh - 140px)` + 内部滚动）：
卡片再高也不可能把标题栏顶出去 —— 那才是 ⚙ 够不着的**根因**。

### 顺带补上的一个洞

"栏位数" 从 3 调到 2 时**原来没有任何检查**：一个 span 2 的卡片塞进 2 轨网格还凑合，
但 "span 2 + span 1 两张卡" 就会**悄悄换到第二行** —— 正好破坏"只有一行"这条规矩。

现在它走和其它布局变更**同一套检查**，但**带 clamp**：

```
columns=2，屏上只有一张 span 3 的卡   → 允许，卡片渲染成 span 2   （缩小，不拒绝）
columns=2，屏上有 span 2 + span 1     → 拒绝并说明：两张都不够小，会换行
```

装不下的那个档位会像其它被拒绝的控件一样**划掉**，鼠标悬停说明原因。

### 视觉

- **两列网格**排布面板行（`minmax(232px,1fr)`）：五个面板挤成一列像一张表单，两列才像一块控制面板。
- **标题带**：`布局` 小标 + `已用 3/3 栏` 徽章 + **✕**，紧贴在一起（`margin-left:auto` 交给关闭按钮，而不是让徽章飞到最右边）。
- **行**：状态点（关=灰 `state-idle`，开=蓝 `state-business`）+ 名称 + 栏位分段控件；名称按钮 `flex:1` 撑满，所以两列的行宽一致。
- **被拒绝的状态只标在"拒绝的那个控件"上**（划掉的栏位按钮），不再给整行套一圈红色虚线 —— 那一行本身没毛病。
- 说明文字改短，`.hud-note` 小字灰色。

## 视觉：外壳透明，卡片与弹层不透明

一条清晰的分工，也是需求本身：

| 层 | 表面 | 为什么 |
|---|---|---|
| `.hud-root` / `.hud-card`（**外壳**） | **完全透明** —— 无背景、无边框、无阴影 | HUD 直接坐在应用自己的背景上，读起来是应用的一部分，而不是贴上去的一块板 |
| `.hud-panel`（**每张卡片**） | **不透明**浮起面板 + 1px 细线 + 柔和投影 | 外壳透明之后，卡片必须自己撑住可读性；卡片才是你看得见的"面" |
| **点击才出现的**（天气详情、图表提示、⚙ 布局编辑器） | **不透明** `--dsw-alias-bg-overlay` | 需要读的浮层不能透 —— 这是上一轮修过的 bug |

设计令牌集中定义在 `.hud-root` 上一次（`--hud-radius` / `--hud-tile` / `--hud-pop` / `--hud-line` /
`--hud-shadow`），所以**新面板继承同一套圆角、表面和细线**，不会各写各的。

其他统一处理：

- **五个面板的卡片头共用一条规则**：`.hud-card .ocq-head,.hud-card .ghh-head,.hud-card .mk-head,.hud-card .bd-head,.hud-card .pk-head{padding:0 0 7px;border-bottom:1px solid var(--hud-line)}`。
  五个面板各画各的头部，外壳给它们**同一条分隔线和间距** —— 这是让五个面板看起来像同一个产品的关键。
  选择器权重 (0,2,0)，所以无论哪张样式表先注入都压得住面板自己的 `.ghh-head{padding:…}`。
- **标题栏那行**加了极淡的渐变蒙版 + `backdrop-filter:blur(8px)`：外壳透明后，聊天记录会直接从那行控件背后滚过去，一行读不清的标题比一条细线更糟。蒙版是**半透明**的，不破坏"外面透明"。
- `⚙` 从一枚带边框的胶囊改成 **20px 圆形图标按钮**（hover 才显出底色），标题栏更安静。
- 品牌字改为 **大写字距**（`HUD`），与 `.hud-pills-label`、`.hud-prefs-label` 一致。
- 卡片 hover 时细线加深一档，作为最轻的反馈。

所有这些都**断言在产出的样式表上**：外壳必须 `background:transparent` + `box-shadow:none` + `border:0`，
卡片必须用 `--hud-tile`，编辑器必须用 `--hud-pop`，`--hud-tile`/`--hud-pop` 必须分别指向
`--dsw-alias-bg-layer-1` / `--dsw-alias-bg-overlay`，五张卡片头必须都被同一条规则覆盖。

### 浮层用什么颜色：一个**蒙层**不是一张**表面**

这里走过两段弯路，都值得记下来：

| 写法 | 结果 |
|---|---|
| `background:var(--dsw-specific-menu)` | **半透明** —— 压在 K 线的红绿蜡烛上，字糊了 |
| `background-color:bg-layer-1` + `background-image:linear-gradient(bg-overlay,…)` | **不透了，但发闷** —— 面板整体变成脏灰色，前景也灰 |

根因是同一个：**`--dsw-alias-bg-overlay` 是"蒙层"，不是"表面"**。设计系统里 overlay 指的是对话框背后
压暗那一层。把它当填充色用，先得到透明，再得到灰。

现在是**一条干净的规则**：

```css
--hud-pop: var(--dsw-alias-bg-layer-1, #ffffff);   /* 浮起表面，和卡片同一个令牌 */
.hud-prefs / .hud-k-tip / .wx-pop / .bd-tip { background: var(--hud-pop); }
```

不透明靠**令牌本身是表面色**来保证（卡片用的就是它），层次感靠**边框 + 投影**来做，而不是靠叠色。
10 处浮层（⚙ 编辑器、K 线提示框与其箭头、Y 轴标签、债市曲线提示框与标签、天气详情、
两张移植卡片）全部统一，测试断言里也直接钉死：**任何浮层的填充里都不许出现 `bg-overlay`**。

### 编辑器的前景色：一级一级往上抬

`label-caption` 是给标点用的，不是给"必须读才能用的标签"用的。所以：

| 元素 | 之前 | 现在 |
|---|---|---|
| `布局` 标题 / `栏位数` 标签 / 说明文字 | `label-caption` | **`label-secondary`** |
| 面板名（关） | `label-caption` + 压暗 | **`label-secondary`**，虚线边框只表示"关" |
| 面板名（开） | `label-primary` | `label-primary` + 蓝色状态点 |
| `已用 3/3 栏` 徽章 | 写死 `#b45309` | **`state-warn-primary`**（暗色主题下才读得出来） |
| ✕ 关闭按钮 | `label-caption` | `label-secondary`，hover 变主色 + 淡底 |

行本身在 hover 时也有淡底反馈，被拒绝的档位仍然划掉 —— 但**不再给整行套红**。
### 日K 只画一个月，细节放进读数里

一年的日线是**一团糊** —— 241 根挤在 300 单位宽的画布里，每根不到 1.2 单位，看不出形态。
现在日K 只取**最近一个月**（实测 22 根，2026-08-31 → 2026-09-30），蜡烛宽到能看清，
**信息量改由提示框承担**：

```
┌ 2026-09-30 ────────────────┐
│ 开 1262.99      高 1271.50 │   ← 2×2，标签与数值分列
│ 低 1255.00      收 1258.62 │
│ 涨跌 -0.35%  -4.37         │   ← 百分比 + 涨跌额，红涨绿跌
│ 振幅 1.31%                 │
│ 量 3.8 万   额 47.97 亿     │   ← 成交量与成交额
│ MA5 1261.24                │
└──────────────▽─────────────┘
```

- **涨跌幅改成对"前收盘"**，不是对当根的开盘价。`(收-开)/开` 是**实体**，不是涨跌幅；
  终端里的涨跌幅一律是"相对上一根收盘"。第一根没有前一根，退回用它自己的开盘价，而不是空着。
- **振幅** = `(高-低)/前收`，**额** = 成交额（`万/亿` 自动换算）。
- 债券 ETF 的 `amount` 也补进了 `parseCandles` —— 提示框要显示它，它就得先活过解析。
- **坐标轴自适应**：根数 ≤ 40 时给 **5 个**日期刻度（一个月 22 根撑得住），否则 3 个；
  刻度按**均匀位置**摆放而不是用蜡烛自身的 x，否则首尾两个标签会被半个标签的宽度切掉。

## 提示框里的涨跌颜色：一个**权重**的坑

"涨跌"要红涨绿跌，但第一次做出来**颜色根本没生效**。原因不是没写颜色，而是**选择器权重**：

```css
.hud-k-kv b    { color:var(--dsw-alias-label-primary) }   /* (0,1,1) —— 赢 */
.hud-k-up      { color:#c0392b }                          /* (0,1,0) —— 输，从未生效 */
```

改成复合选择器就压得住了：`.hud-k-kv b.hud-k-up` 是 **(0,2,1)**。

**而且要"有色但不能看不清"。** 颜色取自主题的**状态令牌**，不是蜡烛那对写死的十六进制：

```css
.hud-k-kv b.hud-k-up  {color:var(--dsw-alias-state-error-primary,#c0392b)}   /* 红涨 */
.hud-k-kv b.hud-k-down{color:var(--dsw-alias-state-success-primary,#1a7f52)} /* 绿跌 */
```

理由：这是**主题表面上的文字**。`#c0392b` 压在半透明的深色提示框上就是"有颜色"里**看不清**的那一半 ——
状态令牌自带亮/暗两套（契约里标了 `requiresLightAndDark`），所以在任何主题上都保证对比度。
蜡烛实体仍然用那对固定色（大面积色块，和图形本身保持一致更重要）。

同一套令牌也铺到了卡片里的涨跌文字（`.mk-up/.mk-down`、`.bd-up/.bd-down`），
它们原本也是写死的深色十六进制，在深色主题下同样会发暗。

### K 线提示框重做

原来四个价格挤在一行（"开 x 高 y 低 z 收 w"），鼠标一动就得眯着眼读。现在是**小卡片**：

```
┌────────────────────────┐
│ 2026-09-30             │  ← 表头（加粗 + 下细线）
│ 开 134.940   高 134.964│  ← 2×2 网格，标签/数值分开
│ 低 134.777   收 134.804│
│ 涨跌 -0.05%   量 1.2万  │  ← 派生数值单独一行（上细线）
└───────────▽────────────┘  ← 小箭头指向那一根蜡烛
```

数值用 `label-primary` 加粗、标签用 `label-caption`，对比明确；等宽数字
（`font-variant-numeric:tabular-nums`）所以鼠标移动时数字不会左右跳。

## 主题令牌：只用契约里的那 14 个

外壳和面板的样式一律走 `--dsw-alias-*`，而且**只用契约里列出的令牌**（可以用 `cordis_inspect_query`
问一下 client 的 `Theme.listTokens`，它会给出当前主题真正承诺的令牌）。这不是洁癖，是一个踩过的坑：

| | |
|---|---|
| **症状** | 点开天气详情后**背景是透明的**，下面的用量卡文字透上来，内容读不清 |
| **原因** | 浮层用了 `--dsw-specific-menu`。它**不在契约列表里**（契约里是 `--dsw-alias-bg-overlay` = "Overlay and popover background"），实际解析出来是**半透明**的 —— 真正的菜单背后有毛玻璃层撑着，而插件里没有 |
| **修复** | 全项目 12 处 `--dsw-specific-menu` 换成 `var(--dsw-alias-bg-overlay,var(--dsw-alias-bg-layer-1,#ffffff))` —— 三个候选**任何一个都是不透明的**，所以这个面再也不会变透明 |
| **另一半** | 标题栏那一行加了 `position:relative;z-index:5`。它是静态盒子且 DOM 在网格之前，从标题栏弹出的浮层会和网格**平级竞争**，于是被卡片盖住 —— 这两条一起才是完整的修复 |
| **5 不够** | 上面那个 `5` 只是"有层叠上下文"，不是"在别人上面"：**每张卡片的表头也是 `position:relative;z-index:5`**（它要压住右侧/底部的拖拽条），而**相同的数字由 DOM 顺序裁决**，标题栏在网格之前 —— 于是每张卡片的**表头**又压回了从标题栏弹出的浮层。用户看到的就是这个：天气详情打开着，股市卡片的表头（股市 · 14:31:44 · ＋添加标的 · 刷新）**从气泡上透出来**，而同一张卡片的**正文**正常待在气泡后面（正文是 `z-index:auto`，所以只有表头漏） |
| **修复（二）** | 标题栏升到 `z-index:20`，卡片表头留在 `5`：这是两个**层级**，不是一个数字。测试断言的是**顺序**（标题栏 > 卡片表头），所以没人需要记住哪个数字更大 |

测试直接**断言在产出的样式表上**（不是断言意图）：浮层必须用契约里的 overlay 令牌、`--dsw-specific-menu`
**不许出现**、`.hud-head` 必须建立 `position:relative` + `z-index` 的层叠上下文、`.hud-panel` **不许**开
自己的 `z-index`（否则又会来抢）、以及 `.hud-head` 的 `z-index` 必须**严格大于**卡片表头那个（相同就是
上面那个"5 不够"的坑，靠 DOM 顺序裁决，标题栏会输）。

## 开发与验证

插件本身**零运行时依赖**。`tools/` 里是只用于开发的工具与测试（不进包）：

```powershell
cd tools
npm install                     # react / react-dom / jsdom，仅测试用
node extract-vendor.mjs         # 从已安装的 app.asar 里解出真 schemastery（+cosmokit）
node build-client.mjs           # 由 fragment 生成 ../client.js
node build-client.mjs --check   # CI 用：client.js 与 fragment 不一致就退出 1
node check-utf8.mjs             # 编码完整性（见下）
node check-jsx.mjs              # 静态：jsx() 不许收数组 children（React 会逐个要 key）
node test-config.mjs            # 配置树：真 schemastery + loader 的 volatile 规则
node test-host.mjs              # 宿主半区：mock ctx + 真实本地 HTTP 上游
node test-client.mjs            # 浏览器半区：jsdom + 真 React 真挂载
npm test                        # 上面全部串起来跑
```

`check-jsx.mjs` 值得单说：`jsx` 与 `jsxs` 的差别（动态 vs 静态）在 JSX 编译后才存在，而**运行时警告只在测试
恰好渲染到那个分支时才出现**。这条规则在本项目里已经被漏过四次，所以改成**静态扫描全部 9 个 fragment**：
扫到就列出文件与行号。它第一次运行就抓到 **3 处从未被测试覆盖的隐患**（`pk-select` 的选项数组、
`linearGradient` 的两个 `<stop>`、`mk-sessions`），全都修掉了。

**四套测试各自守一件事**：

- `test-config.mjs` —— 合并两个插件最容易踩、踩了就致命的地方：配置树。它用**从 app.asar 解出来的真
  schemastery** 构建出真正的 `Config`，再把 loader 里那条规则（`validateVolatilePlacement`，逐字段从
  发行包里读出来的）**原样重新实现一遍**去走这棵树。附**负控**：构造一个必然违规的树，断言走查器确实
  会报错 —— 否则"合法"会因为走查器什么都没走而假绿（真发生过：schemastery 的 schema 是**函数对象**，
  `typeof !== 'object'` 的提前返回让第一次实现完全空转）。还带一条**回归**：把修复前的形状
  （`panels` 自身 volatile）喂进去，断言它**确实被规则拒绝**。
- `test-host.mjs` —— 把**真实插件**挂在 mock cordis context 上，用**真实本地 HTTP 服务**当上游，逐条
  打真实路由：六个面板都挂载、33 条路由全部注册且 `kind: exact`；配额采集器真的取到 42%、`custom`
  端点自动识别出 25%；天气面板在本地 stub 上游上跑完整条链路（IP 定位 → 当前天气 → 预警匹配，
含城市级/省级两档、区划码前缀、非中国地区不给预警源），并断言**缓存命中与强制刷新**、
`HEAD`/405/403 守卫，以及**定位失败时给提示而不是崩**；快递面板同样在本地 stub 上游上跑完
  （本地单号识别 → 关注 → 归一化 → 时间线翻正序 → **变更检测把包裹标未读并按条数计数** → 已读清零），
  并断言未知快递公司代码被拒(400)、重复单号被拒、接口回 `参数错误` 时转成**可执行的**提示；
  两次 GET 命中缓存、`POST /refresh` 真的重新取数、`HEAD` 空 body、错误方法 405、跨站 403、
  坏 ref / 空值 / 坏 JSON 400；**密钥永不出现在响应里**。
- `test-client.mjs` —— 按 DSH 外壳的方式加载 `client.js`，用真 React 真挂载：bundle 以**包名**注册；
  `apply()` 只注册**一个** dock cell；**五张卡片同时在屏幕上**（第六个是标题栏部件），且**同时**在打各自的宿主路由
  （"同时激活"的证据）；网格确实是网格（`data-cols` 在 body 上、`data-span` 在卡片上、两张卡的
  默认栏数来自面板自己的偏好）；**关掉一张卡后 DOM 节点是同一个**（没重挂载 → 没重启轮询）并变成
  胶囊、点胶囊能回来；把栏位数降到 2 时，存着的 3 栏**被夹成 2 栏**且更宽的选项不可点；窄窗口降级
  规则存在；**旧版写下的 `align` 键无法再把卡片压窄**、storage 只留下 `columns` + `layout`；
  一个面板抛错时被 `PanelBoundary` 拦住并具名报告，
  兄弟面板照常渲染。
  它还会**捕获整个干净运行期间的所有 `console.error`，只要出现任何 React 警告就判定失败** ——
  这正是抓出 `jsx`/`jsxs` 误用（数组孩子传给 `jsx`、单个孩子传给 `jsxs`）的那道闸。
- `check-utf8.mjs` —— 这台机器上是 **Windows PowerShell 5.1**：`Get-Content -Raw` + `Set-Content`
  往返会把非 ASCII 静默改写成 `?`（一个 `?` 少 1 字节，且 `node --check` 照样通过）。面板里全是中文
  界面文案，所以每轮都验：无 U+FFFD、UTF-8 往返字节一致、关键中文串仍在。

`extract-vendor.mjs` 解出来的文件用 asar 自带的 **SHA256 完整性块逐个校验**，所以偏移算错不可能伪装成
解压成功（顺带修掉了一个流传很广的偏移写法 `8 + headerSize`，它差 8 字节，产出的是**被截断**的文件）。

### 已知限制

- 面板的**效果函数与事件处理器**里的异常不会被 `PanelBoundary` 捕获（React 只把渲染期异常
  交给边界）。各面板原本就把自己的定时器/请求失败当成尽力而为，这一点与独立运行时一致。
- `panels` 这一层**刻意不是 volatile**，而面板自己的每个字段是。这不是风格问题：loader 的 schema
  构建器会走整棵树，对**任何嵌在另一个 volatile 字段里的 volatile 字段**直接抛
  `volatile fields require a fixed object path without an enclosing volatile field`。
  早期设计把 `panels` 标成 volatile（想让整块配置活生效），结果会让每个"给自己字段标 volatile"的
  面板**在加载期就违规** —— 后果不是"没有设置页"，而是插件配置构建失败。现在改为：外壳不标，
  面板各自标叶子，于是 `panels.quota.cacheMs` 这类编辑仍然是**热生效**的。
  `tools/test-config.mjs` 用真 schemastery + 复刻的规则守着这条线，并把修复前的形状作为回归用例。
- 天气的**极端预警目前只接了中国**（中央气象台）。境外定位不会去问一个查不到的服务：
  返回空列表并标 `source: 'unsupported'`，详情面板直说"该地区暂无预警数据源"。
  接入别家（如美国 NWS）只需在 `fetchAlerts` 里加一个分支。
- 天气**定位靠 IP**（默认）。公司网络/VPN 的出口 IP 可能落在别的城市 —— 那就用
  `panels.weather.city` 或经纬度钉死。IP 结果缓存 24 小时，避免反复请求。
- 栏位与显示偏好是**浏览器本地**的（`localStorage`），不跨机器同步；卡片宽度不是偏好，固定铺满 dock。
- 单进程、单 profile：GitHub 状态在 `$DSH_HOME/storages/dsh-github-hud/state.json`，
  多个 profile 各存各的。
- **数据库卡**（第 3 项）的已知边界，逐条说明而不是含糊带过：
  - **曾经有一个真 bug：这张卡自己点击之后不再重绘。** 现在修好了，而且值得写下来 ——
    它不是猜出来的，是一路量出来的。**根因是一个 `useEffect` 的单行写法**：

    ```js
    const aliveRef = React.useRef(true)
    React.useEffect(() => () => { aliveRef.current = false }, [])   // ← 从不复位
    ```

    ref 初值是 `true`，所以这个写法看起来很对。但**清理函数完全可能在组件还留在屏幕上的时候运行**
    （React 18 的 StrictMode 用「卸载再挂载」来模拟这件事，任何会重跑 effect 的宿主也一样），
    于是这个标志被永久留在 `false` —— 之后每一个 `if (!aliveRef.current) return` 都**静默丢掉自己的更新**：
    卡片保留 DOM、保留事件处理器、照常响应点击（POST 确实发出去了），**然后永远不再重绘**。

    这就是「执行查询后结果表格不出现」的全部原因。**把它钉死的那条证据**是：处理器里 `fetch` 正常返回
    （`ok=true`、2 列 —— 探针打在这一行守卫**之前**，所以能打出来）、渲染计数器一动不动、
    没有重挂载、节点仍连在文档上，而**同一个根节点里其它面板全都正常** —— 因为它们用的都是下面这个
    **会复位**的版本。一行之差：

    ```js
    React.useEffect(() => {
      aliveRef.current = true          // ← 每次 effect 运行都重新武装
      return () => { aliveRef.current = false }
    }, [])
    ```

    顺手查了全部 11 处 `aliveRef`：另外 10 处本来就是对的，只有新写的这张卡漏了。
  - **另有两条是测试自己的错，也记下来**（它们让上面那个 bug 多藏了两轮）：
    一是刷新按钮读的是 `/refresh` 路由，而测试只替换了 `/state` 的桩 —— 卡片于是"无视"了一个它
    **从未收到**的载荷；二是空连接状态下卡片的「刷新」**本来就是禁用的**（没有东西可刷新，这是对的），
    测试却在那时去点它。两条都修了，断言也就全绿了：结果表格、连不上、空列表现在**都有断言**。
  - **MySQL 的 `caching_sha2_password` 完整认证不支持**：它需要 TLS 或服务器的 RSA 公钥，
    在明文连接上做这件事等于降级。卡片会直说这一点，而不是报「access denied」让人去查权限。
    快路径（服务器已缓存该密码的哈希）是支持的，MariaDB 的 `mysql_native_password` 也是。
  - **PostgreSQL 的 GSSAPI / SSPI / 证书认证不支持**：需要系统凭据，不在零依赖的范围内。服务器要求时会报出认证代码。
  - **SQLite 的 API 是同步的**：`node:sqlite` 没有中断接口，一个很慢的查询会占住宿主进程若干秒 ——
    行数上限限制的是读回多少，不是引擎想多久。卡片如实标注，而不是暗示超时是一道它做不到的硬闸。
  - **不支持的数据库**（Oracle、SQL Server、MongoDB …）**没有驱动**：类型写错会退回 SQLite 而不是崩溃，
    而卡片只会列出它真的能用的引擎（通过 `available()` 当场询问，而不是照版本号猜）。
